# Claude quota additions

This pinned plugin preserves the upstream OAuth quota path and the existing
Enterprise monthly spend-limit patch. It also observes subscription quota on
normal Anthropic HTTP responses when the active OpenCode connection uses `key`
(including a token generated by `claude setup-token`). It never sends inference
requests to obtain quota or changes authentication.

The existing quota panel displays the provider's unified 5-hour and weekly
utilization/reset headers. Ordinary API request/token rate limits are not
subscription quota and are ignored. Until a normal Claude request supplies valid
headers, `/quota_status` reports `Awaiting quota headers from a normal Claude
request.` No quota values are invented.

Observations stay in memory for at most five minutes, never beyond their window
reset, and are invalidated on credential changes and plugin cleanup. Requests
crossing a credential switch are discarded. Only official Anthropic `/v1/messages`
HTTP responses are used; proxies and WebSockets do not populate this source.
No tokens, request bodies or response bodies are read by the observer.

The shared Home Manager option selects this package by default on Linux and
Darwin; `home.opencode.quotaPlugin = null` retains the unpatched npm plugin.
Deployment and service restarts are separate user actions. After activation,
make a normal Claude request and inspect `/quota_status` for
`quota_source: response_headers`. Header availability on an actual account must
be checked there; synthetic tests cannot prove it.
