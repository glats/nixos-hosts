# Battery Warning Specification

## Purpose

Two-tier low-battery protection for t14 (ThinkPad T14 AMD Gen 4, Omarchy/Hyprland):
1. **UPower system warnings** at 15% and 8% (D-Bus level, visible to desktop environments via the UPower daemon)
2. **Omarchy mako notification** at ≤10% (user-facing, from the `omarchy-battery-monitor` script)
3. **Graceful poweroff** at 5% via UPower `criticalPowerAction = "PowerOff"`

Ensures the user receives a visual low-battery warning and the system performs a graceful poweroff before the embedded controller (EC) cuts power at 0%, preventing dirty shutdowns and btrfs corruption.

## Architecture Note: Two-Tier Design

The battery warning system combines two independent mechanisms:

| Layer | Threshold | Mechanism | Target |
|-------|-----------|-----------|--------|
| UPower system warning | ≤15% discharging | UPower D-Bus `percentageLow` signal | System-wide, visible to desktop environment power managers |
| Omarchy mako notification | ≤10% discharging | `omarchy-battery-monitor` script → `notify-send` → mako | User-facing popup, once per discharge cycle |
| UPower system critical warning | ≤8% discharging | UPower D-Bus `percentageCritical` signal | System-wide |
| UPower critical action | ≤5% discharging | `criticalPowerAction = "PowerOff"` | Clean shutdown |

The omarchy notification is independent of UPower's own warnings — it provides a user-visible mako popup that UPower's system-level D-Bus signals do not generate on Hyprland.

## Requirements

### Requirement: Low Battery Notification (Omarchy Mako)

The system SHALL display a mako notification when the battery percentage drops to or below 10% (the `BATTERY_THRESHOLD` in the omarchy script) while discharging. The notification SHALL fire at most once per discharge cycle via a flag file at `/run/user/$UID/omarchy_battery_notified`. The `omarchy-battery-monitor` user service SHALL be active and running, triggered by a systemd timer.

#### Scenario: Battery reaches 10% while discharging

- GIVEN t14 is running on battery power at 11%
- WHEN the battery discharges to 10%
- THEN a mako notification with "Time to recharge!" appears
- AND the `omarchy-battery-monitor` service is `active (running)`

#### Scenario: Notification fires only once per cycle

- GIVEN the low-battery notification has already fired at 10%
- WHEN the battery continues discharging to 9%, 8%, 7%
- THEN no additional mako notifications appear
- AND the notification flag file exists at `/run/user/$UID/omarchy_battery_notified`

#### Scenario: UPower system warning at 15% (no mako)

- GIVEN t14 is running on battery power at 16%
- WHEN the battery discharges to 15%
- THEN UPower emits a system-level `percentageLow` D-Bus signal
- BUT no mako notification is generated by this event
- AND the omarchy notification flag file does NOT exist yet

### Requirement: Critical Battery Warning (UPower System)

The system SHALL emit a UPower system-level critical warning when the battery percentage drops to or below 8% while discharging. This is a D-Bus signal from the UPower daemon, distinct from the omarchy mako notification.

#### Scenario: Battery reaches 8% while discharging

- GIVEN t14 is running on battery power at 9%
- WHEN the battery discharges to 8%
- THEN UPower emits a `percentageCritical` D-Bus signal
- AND the UPower `percentageCritical` threshold is set to 8
- BUT no additional mako notification is generated by this event (the omarchy popup already fired at 10%)

### Requirement: Clean Poweroff at Critical Threshold

The system SHALL perform a graceful poweroff when the battery percentage drops to or below 5% while discharging. The poweroff SHALL flush journald and unmount btrfs cleanly before halting.

#### Scenario: Battery reaches 5% while discharging

- GIVEN t14 is running on battery power at 6%
- WHEN the battery discharges to 5%
- THEN UPower triggers `criticalPowerAction = "PowerOff"`
- AND the system performs a clean shutdown (journald flushed, btrfs consistent)
- AND the EC does NOT cut power abruptly at 0%

### Requirement: No Action While Charging

The system SHALL NOT fire any low-battery notification, critical warning, or poweroff action while the battery is charging or fully charged.

#### Scenario: AC adapter plugged in at low battery

- GIVEN t14 battery is at 10% and the AC adapter is plugged in
- WHEN the battery state changes to `charging`
- THEN no low-battery notification fires
- AND no critical warning fires
- AND no poweroff action triggers
- AND the notification flag file is removed (reset for next discharge cycle)

### Requirement: Host Isolation

The UPower battery-warning configuration SHALL only apply to hosts that import `modules/hardware/amd-laptop.nix`. Hosts that do not import this module SHALL NOT have UPower enabled by this change.

#### Scenario: Non-t14 hosts unaffected

- GIVEN `rog` and `thinkcentre` do not import `modules/hardware/amd-laptop.nix`
- WHEN the `services.upower` block is added to `amd-laptop.nix`
- THEN `rog` and `thinkcentre` configurations remain unchanged
- AND `services.upower.enable` remains `false` (default) on those hosts
