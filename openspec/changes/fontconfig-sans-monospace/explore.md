# Exploration: fontconfig sans/monospace separation

## Problem Statement

`modules/desktop/fonts.nix` produces a single fontconfig policy: every
generic family (`sans-serif`, `serif`, `monospace`, `sans`, `mono`) gets
resolved by the same set of strong aliases (`Source Sans 3` → `Noto Sans`
for sans, `CaskaydiaCove Nerd Font` → `Noto Sans Mono` for monospace).

The user wants:

1. Terminals, text editors, and any fixed-width text surface
   (ghostty/kitty/alacritty, neovim, tmux status, btop, conky, hyprlock
   input, walker, mako, waybar) keep using `CaskaydiaCove Nerd Font`
   (monospace + Nerd Font glyphs).
2. GUI apps that should look "normal" (GTK/Qt apps: nautilus, brave,
   evince, gnome-text-editor, gnome-calculator, MATE panel/caja, etc.)
   resolve `sans-serif` to a real sans family (Source Sans 3 / Noto
   Sans) and never accidentally fall back to a monospace font.
3. Web pages must keep their own font choices (no fontconfig rule that
   disturbs the browser engine's own family resolution).
4. The user wants suggestions for other apps that may need explicit
   overrides.

There is currently a single global strong alias per family, and the
swayland `font-family` style on the omarchy waybar is hard-coded to
`'JetBrainsMono Nerd Font'` (terminal-style). The T14 already opts out of
omarchy's HM fontconfig (`fonts.fontconfig.enable = lib.mkForce false`
in `hosts/t14/home/omarchy.nix`), so the system-level `modules/desktop/fonts.nix`
is the only fontconfig authority on every Linux host.

## Current State

### How fonts flow from system → apps today

System-level (`modules/desktop/fonts.nix`, imported by `rog` via
`modules/profiles/desktop.nix`, by `thinkcentre` the same way, and by
`t14` directly in `hosts/t14/default.nix`):

- `fonts.fontconfig.enable = true`
- `fonts.fontconfig.localConf` is a single block of fontconfig XML that
  defines:
  - `<rejectfont>` for Liberation, DejaVu, Arimo, Tinos, Cousine
  - `<match target="pattern">` redirects:
    - `Arial`/`Helvetica`/etc. → `sans-serif`
    - `Times`/`Times New Roman` → `serif`
    - `Courier`/`Courier New`/`Terminal` → `monospace`
  - `<match target="pattern">` forces `monospace`/`mono` →
    `CaskaydiaCove Nerd Font`
  - `<alias binding="strong">` for `sans-serif`/`sans`
    → `[Source Sans 3, Noto Sans]`, `serif` → `[Source Sans 3, Noto Serif]`,
    `monospace` → `[CaskaydiaCove Nerd Font, Noto Sans Mono]`
  - `<alias binding="weak">` adds JoyPixels/Noto Color Emoji as emoji
    fallbacks for all four generic families.
- `fonts.fontconfig.defaultFonts` sets the same defaults the
  `localConf` strong aliases use.
- `fonts.packages` installs Source Sans, CaskaydiaCove Nerd Font, Nerd
  Fonts symbols-only, Symbola, joypixels, noto-fonts, noto-fonts-cjk-sans.

`modules/desktop/kmscon.nix` (console / virtual terminal):

- Hard-codes `font-name = "CaskaydiaCove Nerd Font Mono"`. Already
  monospace.

Per-app font settings (not from fontconfig, take priority):

- `home-linux/ghostty.nix` — `font-family = "CaskaydiaCove Nerd Font"`.
  Mono. Single source of truth on all three Linux hosts.
- `home-linux/kitty.nix` — `programs.kitty.font.name = "CaskaydiaCove Nerd Font"`.
  Mono. (Direct `imports` in `home-linux/shared-modules.nix` and on t14
  from `hosts/t14/home/default.nix`.)
- `home-linux/alacritty.nix` — does NOT set a font at all; omarchy's
  alacritty theme (`config/themes/<theme>/alacritty.toml`, generated by
  `theme-generator.nix`) sets `[font] size = 12.0` but no family.
  Without a family, alacritty will fall through to Pango/fontconfig and
  resolve to whatever the system monospace alias is. On t14 the
  system-level monospace alias is CaskaydiaCove Nerd Font (good); on
  rog/thinkcentre the same file produces the same result. **However,
  the alacritty `programs.alacritty.settings` block in
  `home-linux/alacritty.nix` does not declare `font`, and the omarchy
  alacritty theme does not include a `family` line either, so the
  effective font depends entirely on fontconfig.** This is fragile.
- `home-linux/mate.nix` line 240 — `mate-terminal` profile sets
  `font = "CaskaydiaCove Nerd Font 11"`. Mono. Only on MATE hosts
  (rog/thinkcentre, NOT t14).
- `home-darwin/windsurf.nix`, `home-darwin/vscode.nix` — VS Code
  `editor.fontFamily = "'CaskaydiaCove Nerd Font', 'monospace', monospace"`.
- `home-linux/rofi.nix` — `programs.rofi.font = "Sans 12"` AND the
  custom rasi theme references `font: "Sans 14"` / `"Sans 12"`. Rofi
  resolves the "Sans" family via Pango → fontconfig. The system
  monospace strong alias only matches the family name `mono` or
  `monospace`, so "Sans" goes to the sans-serif alias chain and gets
  Source Sans 3. **That already produces a sans font for rofi today, but
  by accident**: the user would not have noticed because Rofi is the
  only place in the config that asks for "Sans" by name.
- `home-linux/conky-rog.nix`, `home-linux/conky-thinkcentre.nix` —
  Conky `font = 'CaskaydiaCove Nerd Font:size=12'`. Hard-coded mono.
- `hosts/t14/home/hypr/hyprlock.nix` line 54 — `font_family = "Source Sans Pro"`.
  t14 only. **This is a sans font in a screen-locker context, which
  is exactly the "GUI-app should be sans" case the user is asking for.
  This is the one place in the repo where the user has already
  manually selected a sans font for a non-terminal context.**
- `hosts/t14/home/omarchy.nix` line 54 — upstream omarchy
  `hyprlock` config uses `font_family = "CaskaydiaMono Nerd Font"`,
  overridden by t14 to `Source Sans Pro`.

Apps whose font comes from the omarchy theme generator
(`modules/home-manager/theme-generator.nix` in omarchy-nix — NOT
vendored in this repo, lives at the flake input):

- `waybar.css` — color tokens only; the actual `font-family` is in
  `config/waybar/style.css` line 10, hard-coded to
  `'JetBrainsMono Nerd Font'`. **This is the only file that decides
  waybar's font, and it picks a monospace Nerd Font for a GUI bar.**
- `swayosd.css` (in `swayosd.nix` line 29) — `font-family: 'JetBrainsMono Nerd Font'`.
  Mono. (Volume/brightness OSD.)
- `walker.css` (in `walker-theme/style.css` line 8) —
  `font-family: monospace`. Walker is a GTK app that resolves the
  CSS `monospace` family via fontconfig → CaskaydiaCove Nerd Font.
  Mono.
- `mako.ini` is generated by `mkMako` in theme-generator.nix
  (lines 257–264), and the static `default/mako/core.ini` (line 8)
  sets `font=sans-serif 14px`. **Mako already requests `sans-serif`,
  so today it resolves to Source Sans 3 / Noto Sans — exactly what the
  user wants for a notification OSD. The current behaviour is correct
  and we should preserve it.**
- `hyprlock.conf` (generated) — only sets `$color`/`$inner_color`/etc.
  The actual `font_family` is set per-host in
  `hosts/t14/home/hypr/hyprlock.nix` (`Source Sans Pro` on t14) and
  comes from omarchy-nix upstream elsewhere.
- `alacritty.toml`, `kitty.conf`, `ghostty.conf` — color tokens only;
  the active font is set by the `programs.<x>.font.*` NixOS options,
  not by the theme.

GTK theme + Qt settings (`home-linux/theme.nix`, **NOT imported on t14**
— t14's omarchy HM module provides its own `gtk` block and the t14
overrides live in `hosts/t14/home/omarchy.nix`):

- `gtk.theme.name = "Materia-dark-compact"` (rog/thinkcentre).
- `gtk.gtk3.extraConfig."gtk-application-prefer-dark-theme" = true`.
- `gtk.gtk4.extraConfig."gtk-application-prefer-dark-theme" = true`.
- `qt.style.name = "adwaita-dark"`, `qt.platformTheme.name = "gtk"`.
- dconf `org/gnome/desktop/interface`.`color-scheme = "prefer-dark"`.

The Home Manager `gtk` module (verified via
`nixos_nix search "gtk theme font name" type=options` and the
home-manager upstream `gtk.nix`) does **not** expose a `gtk.font` or
`gtk.fontName` option. The system-level `fonts.fontconfig.defaultFonts`
plus the user-level `~/.config/gtk-3.0/settings.ini` (generated by
`home-manager`'s `gtk` module) `gtk-font-name` key is the GTK3/4
default font path. On MATE hosts, `home-linux/mate.nix` already sets
the MATE dconf keys including the per-profile mate-terminal font; on
t14 the GTK default is controlled by the theme.

## Affected Areas

- `modules/desktop/fonts.nix` — the single authority for fontconfig on
  every Linux host. The `<alias binding="strong">` blocks and the
  `forceMatch` of `monospace`/`mono` are the core of the problem.
- `modules/desktop/kmscon.nix` — already monospace; no change needed.
- `home-linux/rofi.nix` — already uses "Sans 12/14" by name; works
  today by accident (Pango resolves via fontconfig). No change needed
  unless the user wants to switch rofi to mono (they don't — rofi is a
  GUI app launcher).
- `home-linux/alacritty.nix` — has no `programs.alacritty.settings.font`
  block. The omarchy theme's `alacritty.toml` sets size but not
  family. Today alacritty resolves to CaskaydiaCove Nerd Font by
  default because the user is running a shell. **Should explicitly set
  font-family here for robustness.**
- `home-linux/ghostty.nix` / `home-linux/kitty.nix` — already mono.
  No change.
- `home-linux/mate.nix` — mate-terminal profile already mono. No change.
- `home-linux/conky-rog.nix` / `home-linux/conky-thinkcentre.nix` —
  hard-coded mono. No change.
- `hosts/t14/home/hypr/hyprlock.nix` — t14-only sans font for
  hyprlock. **Already does what the user wants.** No change.
- `home-linux/theme.nix` — sets GTK theme + Qt style + dconf dark
  scheme. Does NOT set a default font. **No change unless we add
  `gtk.font = { ... }` which is not an HM option** (we have to use
  dconf / `gtk.gtk3.extraConfig` / `xdg.configFile."gtk-3.0/settings.ini"`
  with a `gtk-font-name` key, or use the dconf
  `org.gnome.desktop.interface font-name` / `document-font-name` /
  `monospace-font-name` keys). dconf is the right tool.
- `home-darwin/{ghostty,vscode,windsurf}.nix` — already configured
  with explicit CaskaydiaCove. No change.
- omarchy-nix inputs (vendored in `/tmp/omarchy-nix/` for reference,
  not in the repo) — `config/waybar/style.css` (line 10),
  `walker-theme/style.css` (line 8), `modules/home-manager/swayosd.nix`
  (line 29) hard-code mono. These are external files that the
  flake pins via `inputs.omarchy-nix.url`; we don't edit them
  directly. We have to override their style files in
  `hosts/t14/home/` to change the font, or accept the mono default
  for waybar/walker/swayosd on t14.
- `hosts/t14/home/default.nix` (waybar config) — only sets modules
  and per-module config; the `font-family` is in
  `xdg.configFile."waybar/style.css"` (deployed by omarchy-nix from
  `config/waybar/style.css`). T14 does not override that file, so
  waybar today renders with `'JetBrainsMono Nerd Font'`.

| Console (kmscon) | CaskaydiaCove Nerd Font Mono | Mono | None |

| Spotify, Discord, Steam, webapps | Uses fontconfig defaults | Respects fontconfig | If a user reports a bad font, we add a per-app test (e.g. `test name="application"`) but that is a separate future change. |

The actual **gaps** are:

1. **Waybar** on t14 uses `JetBrainsMono Nerd Font`. The user wants
   sans. This is set by an external file
   (`/tmp/omarchy-nix/config/waybar/style.css` line 10) and needs an
   override in `hosts/t14/home/`.
2. **Swayosd** on t14 uses `JetBrainsMono Nerd Font` (omarchy-nix
   `modules/home-manager/swayosd.nix` line 29). Needs the same
   override pattern.
3. **Alacritty** has no explicit font family set anywhere in this repo
   (only the size is set by the theme generator). This is fragile
   because alacritty will fall through to fontconfig and could
   pick up a different monospace if the strong alias ever changes.
   Should be explicit.
4. **No per-app fontconfig test rules** — currently the fontconfig
   uses a single global strong alias per family. If we want a future
   where a specific app is forced to a specific font (e.g. "Spotify
   must use Source Sans 3 even though it asks for `system-ui`"),
   we need a per-app `<match target="pattern">` with a
   `<test name="application">` qualifier. Not needed today, but
   worth sketching in the design.

## Approaches

### Option A — Override the two omarchy CSS files on t14

Edit `hosts/t14/home/default.nix` (already waybar's home) and create a
new `hosts/t14/home/swayosd.nix` to deploy the override CSS, plus
`xdg.configFile."waybar/style.css".text` with the same shape as
omarchy's `style.css` but `font-family: 'Source Sans 3', 'Noto Sans', sans-serif`.

- **Pros**: Minimal blast radius. Two files change. The rest of the
  repo is untouched. No risk of regressing GTK/terminals.
- **Pros**: Matches what t14 already does for hyprlock
  (`font_family = "Source Sans Pro"`), mako (`font=sans-serif 14px`),
  walker (which is already sans in spirit, although Pango picks mono
  from fontconfig because walker.css uses `monospace`).
- **Cons**: Doesn't add a per-app fontconfig test rule, so if a future
  app asks for "monospace" and the user actually wants it to be sans,
  the user has to remember to override that app's CSS too. **But this
  is fine** because the user wants `monospace` to mean monospace in
  fontconfig (terminal semantics), and "want sans" means a CSS-level
  choice in the app's stylesheet.
- **Effort**: Low. ~20 lines changed across two files.

### Option B — Add a per-app fontconfig test rule

Use `<match target="pattern"><test name="application"><string>spotify</string></test>...</match>`
inside `localConf` to override the font for a specific app, and
similarly for any other GUI app.

- **Pros**: Single place to control all app font overrides. Aligns with
  the "single source of truth" model the user wants.
- **Cons**: Web browsers (Chromium, Firefox) send patterns that look
  exactly like GTK apps, so a careless rule can hijack web font
  resolution. Need to be very careful to test only specific app IDs.
  Also doesn't help waybar (which renders via Pango/CSS, not
  fontconfig), nor mako (which already gets sans), nor swayosd (CSS).
- **Cons**: Overkill for the current scope (user only flagged waybar +
  mako + nautilus, and mako is already correct).
- **Effort**: Medium. ~50–80 lines for the rules + careful testing
  with `fc-match` per app.

### Option C — Make every app pick its own font via dconf/GTK CSS/its
own config file

Audit every app and add an explicit font setting. Most of them
already work via fontconfig; only waybar/swayosd need overrides.

- **Pros**: Most explicit, no surprise interactions.
- **Cons**: Lots of churn, most of it redundant with what fontconfig
  already does.
- **Effort**: High. Easy to introduce drift between hosts.

### Option D — Combination: Option A (override two CSS files) + add
the per-app fontconfig test rule scaffold for future use

- **Pros**: Solves the immediate problem (waybar, swayosd) cleanly
  while leaving a documented hook in `localConf` for future per-app
  rules.
- **Cons**: Slightly more code than Option A alone.
- **Effort**: Low–Medium.

## Recommendation

**Option A is the right move today.** Reasons:

1. The two real gaps (waybar and swayosd) are CSS-level, not
   fontconfig-level. Putting the override in CSS matches the layer
   the app already uses for its other style overrides (the omarchy
   theme generator already deploys `~/.config/omarchy/current/theme/waybar.css`
   for colors and `~/.config/omarchy/current/theme/swayosd.css` for
   colors; t14 only needs to override the `*` `font-family` line
   in the static CSS that imports those theme files).
2. mako is already correct. nautilus is already correct. hyprlock is
   already correct. The only work is two CSS overrides.
3. Alacritty is a real but separate concern — it has no explicit
   `programs.alacritty.settings.font.family` in `home-linux/alacritty.nix`
   and the omarchy theme doesn't set `family` either. **Add a
   `programs.alacritty.settings.font.family = "CaskaydiaCove Nerd Font"`
   line in `home-linux/alacritty.nix` so the explicit font is the
   same on every host.** This is Option C for one file and it's
   worth doing.
4. Option B (per-app fontconfig test rule) is the right **future**
   tool but is not needed today. Sketch it in the design doc as a
   follow-up so the user knows the pattern is available.

## Suggested apps that may need font overrides in the future

These are the apps that commonly need an explicit font override
because either the default `sans-serif` doesn't fit (mono is
expected) or the default is something other than Source Sans 3:

1. **Steam** (`steam`) — Big Picture and library views ask for
   "Motiva Sans" which is not in the package set. Resolves to whatever
   the system sans is today. Not a real problem, but worth knowing.
2. **Spotify** (`spotify`) — Asks for "Circular" / "system-ui".
   Resolves to sans today. If the user reports it, we can add a
   `<test name="application"><string>spotify</string></test>` rule.
3. **Discord** (`discord`) — Asks for "gg sans" (now "gg sans
   normal"). Resolves to sans today. Common complaint on Linux.
4. **Code OSS / VS Code** — Already has explicit font
   (CaskaydiaCove Nerd Font) via the `editor.fontFamily` setting in
   `home-darwin/{vscode,windsurf}.nix`. On Linux, the `vscode` Nix
   module also accepts a `userSettings` block. Should be the same.
5. **Obsidian** — Asks for "Inter" by default. Resolves to sans. If
   the user wants it monospaced, set in Obsidian's appearance
   settings (not fontconfig).
6. **Telegram Desktop** — Asks for "Open Sans". Resolves to sans.
7. **Firefox** — Has its own font settings (about:preferences). The
   user already has a preference for `system-ui`. **No fontconfig
   change** — web content should not be hijacked.
8. **Chromium / Brave / Chrome** — Same as Firefox. **No
   fontconfig change** — web content must not be hijacked. The GTK
   chrome (tabs, menus) will use whatever fontconfig says.
9. **gnome-text-editor / gedit** — GTK app, resolves to sans today.
   Good.
10. **evince / papers / zathura** — zathura is configurable per-app
    (`~/.config/zathura/zathurarc` with `set font`); evince and
    papers use GTK sans by default and are fine.
11. **walker** (omarchy launcher, t14) — Already uses `font-family:
    monospace` in the static CSS. Pango resolves to
    CaskaydiaCove Nerd Font. This is actually a candidate for
    switching to **sans** because walker is a GUI launcher, not a
    terminal. But the user hasn't asked. Worth a heads-up in the
    proposal as a follow-up question.
12. **btop** (omarchy module) — A TUI; mono is correct. No change.
13. **wofi** (t14 `SUPER+SHIFT+R` binding) — `wofi --show run` uses
    Pango. With no `wofi/style.css` override, wofi falls back to
    the GTK theme's default font. Worth knowing if the user reports
    a font issue.
14. **swayidle / hypridle** — No text. Not relevant.
15. **pipewire / wireplumber** — No text. Not relevant.

  `/tmp/omarchy-nix/default/mako/core.ini` line 8

## Risks

- **Risk: walker is currently mono by CSS accident.** The walker
  static CSS uses `font-family: monospace`, which Pango resolves to
  CaskaydiaCove Nerd Font. If the user actually wants walker to be
  sans (because it's a GUI launcher), that's a third file to
  override. **Confirm with the user in the proposal step** whether
  walker should stay mono (TUI-like aesthetic) or move to sans.
- **Risk: omarchy-nix upgrades.** A future omarchy-nix release may
  change the `config/waybar/style.css` or `swayosd.nix` files. The
  override on t14 is in `hosts/t14/home/` so it does not affect
  upgrades, but we should keep the override minimal and self-explanatory.
- **Risk: alacritty on hosts that don't import the omarchy theme.**
  Rog/thinkcentre import the omarchy theme via the btop module, but
  they don't import the omarchy `alacritty.nix` HM module (only
  `home-linux/alacritty.nix` is in `shared-modules.nix`). On those
  hosts alacritty today uses the same fontconfig default. Setting
  `programs.alacritty.settings.font.family = "CaskaydiaCove Nerd Font"`
  in `home-linux/alacritty.nix` will be a behavior-neutral upgrade
  on rog/thinkcentre and a positive fix for t14 (where alacritty is
  not the default but is installed by omarchy).
- **Risk: a future per-app fontconfig rule for "Chromium" /
  "firefox" would hijack web fonts.** This is the strongest reason
  to keep per-app rules out of `localConf` and at the app-config
  layer. The design doc must call this out.
- **Risk: `fonts.fontconfig.enable = lib.mkForce false` on t14.**
  If omarchy-nix ever changes the key name (e.g. to
  `fonts.fontconfig.package` or removes the option entirely), t14's
  `mkForce false` will break the build. Worth wrapping in a
  `lib.mkIf (config ? fonts.fontconfig.enable)` guard, but that
  is out of scope for this change.

## Ready for Proposal

**Yes.** The user has a clear, narrow requirement (sans for GUI
non-terminal apps, mono for terminals, don't disturb the web). The
gaps are small (waybar + swayosd + alacritty-explicit). The
recommended approach (Option A + the alacritty fix) is small
enough to be a single PR with 1–3 file edits and is below the
400-line review budget.
