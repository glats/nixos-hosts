# Delta for Hyprland Workspace Initialization

## ADDED Requirements

### Requirement: Declarative Default Workspace per Monitor

Each docked external monitor SHALL have exactly one workspace assigned as `default:true`, ensuring Hyprland creates that workspace on the correct monitor at session start.

| Monitor (descriptor) | Default Workspace |
|---|---|
| `AOC 24P1W1 OTNQ4HA000101` | 1 |
| `Lenovo Group Limited LEN G24-10 U5B4GWF1` | 2 |
| `AOC 2470W GGZM3HA438259` | 3 |
| `eDP-1` (undocked / laptop-only) | 1 |

The `default:true` flag SHALL be appended to the first workspace rule for each monitor in the `workspace` list generated by `mkWorkspaceRules`.

#### Scenario: Docked startup — workspaces appear on correct monitors

- GIVEN the dock is connected with all three external monitors
- WHEN the Hyprland session starts
- THEN workspace 1 is created on `desc:AOC 24P1W1 OTNQ4HA000101`
- AND workspace 2 is created on `desc:Lenovo Group Limited LEN G24-10 U5B4GWF1`
- AND workspace 3 is created on `desc:AOC 2470W GGZM3HA438259`

#### Scenario: Undocked startup — laptop panel gets default workspace

- GIVEN only the laptop panel (eDP-1) is active, lid open
- WHEN the Hyprland session starts
- THEN workspace 1 is created on `eDP-1`

#### Scenario: Hyprland startup race mitigation

- GIVEN `default:true` may not take effect on first config parse (Hyprland issue #5464)
- WHEN the `monitor-lid-validator.sh` daemon completes its `apply()` function
- THEN `hyprctl reload` is invoked to re-evaluate workspace rules

### Requirement: Persistent Workspaces Across Empty State

All workspaces assigned via `mkWorkspaceRules` SHALL include the `persistent:true` flag so they remain visible in Waybar and Hyprland even when no windows occupy them.

#### Scenario: Workspace survives window removal

- GIVEN workspace 2 on the Lenovo monitor has no windows
- WHEN the user moves the last window away from workspace 2
- THEN workspace 2 remains listed in Waybar and is switchable via `hyprctl dispatch workspace 2`

#### Scenario: All three primary workspaces always visible when docked

- GIVEN the dock is connected
- WHEN the session is idle with no windows open
- THEN workspaces 1, 2, and 3 are all present and visible in Waybar

### Requirement: eDP-1 Workspace Rules in Laptop-Only Mode

When `ENABLE_LAPTOP` is true, the configuration SHALL include workspace rules binding workspaces 1, 2, and 3 to `eDP-1` so that undocked sessions have persistent, defaulted workspaces on the laptop panel.

#### Scenario: Undocked — workspaces 1-3 available on eDP-1

- GIVEN the laptop is undocked with lid open
- WHEN the user switches to workspace 2 or 3
- THEN those workspaces are created on eDP-1 and remain persistent

### Requirement: Daemon-Triggered Reload on Monitor Changes

The `monitor-lid-validator.sh` daemon SHALL invoke `hyprctl reload` at the end of every `apply()` call, ensuring workspace rules are re-evaluated after monitor layout changes (dock, undock, lid toggle).

#### Scenario: Dock event triggers workspace re-assignment

- GIVEN the system is running with only eDP-1 active
- WHEN the user connects the dock and all three external monitors appear
- THEN `monitor-lid-validator.sh` detects `monitoradded` events, runs `apply()`, and calls `hyprctl reload`
- AND workspaces 1, 2, 3 are re-assigned to their correct external monitors

#### Scenario: Lid close triggers layout + reload

- GIVEN the laptop is docked with lid open
- WHEN the user closes the lid
- THEN `apply()` disables eDP-1, moves externals to y=0, and calls `hyprctl reload`
