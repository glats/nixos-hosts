### Consumer pattern in this repo

The pattern is well-established (see `restore-omarchy-hyprland-ownership`
design #1345):

> Upstream owns; downstream's role is: (a) opt-in via `omarchy.*` options,
> (b) `mkDefault` overrides only on t14-specific values, (c) `mkForce` only
> when an upstream key collides with a t14 value the user *must* change.

This is the same pattern the btop refactor used: drop local `mkIf hostName`
conditionals, import the upstream module directly, rely on attrset merging
and priority rules.

### How external flakes pass through modules (NixOS discourse, flake.parts)

From `flake.parts/best-practices-for-module-writing`:

> "In a configuration, you may take shortcuts which have little impact, but
> shortcuts in a reusable module lead to surprises for your module's users."

The nix-best-practices consensus: **modules should make no assumption about
which inputs are present**; the user bundles them. t14 is a single
configuration, so it can use `mkForce` for genuine per-host overrides — but
should not duplicate logic upstream has already provided.

## Risk Assessment

### Hard dependencies (cannot break)

1. **Boot must still work.** t14 uses xfs root + LUKS + systemd-boot. Any
   change to `hardware-configuration.nix` or `boot.initrd.supportedFilesystems`
   is a brick-risk. **Do not touch.**

2. **Hyprland session must launch.** This requires `programs.hyprland.enable`
   + `services.greetd` + the `hyprland-uwsm` session entry. omarchy-nix
   already owns all three. We must not break the wiring.

3. **Sops decryption must work for t14.** `.sops.yaml` uses `*host_t14` for
   every secret. `sops.age.sshKeyPaths` is set in
   `hosts/t14/home/omarchy.nix:92`. **Do not touch** either.

4. **Standalone `hms` (HM standalone on t14) must keep working.** The
   `osConfig` workaround in `flake.nix:269-285` is fragile and documented in
   `docs/hms-t14-standalone-hm.md`. Any change to omarchy-nix's HM module
   that re-reads `osConfig.omarchy` will re-break this. The refactor must
   not change the upstream HM module's `osConfig` handling.

### Soft risks (can break, fixable)

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| Waybar config drift after switching to upstream | Medium | Compare `hosts/t14/home/default.nix:104-346` vs `omarchy-nix:config/waybar/config`. Only 1 functional delta (`custom/iwd-wifi`). Diff and verify. |
| Waybar indicators path changes (`indicators/iwd-wifi.sh`) | Low | Use a different path or add to upstream's `config/waybar/indicators/` |
| `gtk.iconTheme = Papirus-Dark` lost when `omarchy.gtk.iconTheme` becomes upstream default `unset` | Medium | If upstream adds the option with default `"Papirus-Dark"`, no risk. If they make it required, t14 picks up. Verify before apply. |
| `hyprlock` color source breaks when t14 drops its own source line | Medium | Upstream's `hyprlock.nix` already sources the theme (`color = backgroundRgb` from palette). The t14 source line is redundant — drop it. |
| `hyprsunset` schedule breaks if `omarchy.hyprsunset.schedule` option has different attrset shape | Low | Mirror upstream `[{time, identity?, temperature?}]` exactly. |
| `hypridle` lock-delay: t14 wants 200s for screensaver visibility; upstream 151s = screensaver cut | Medium | Push `omarchy.hypridle.lock_delay` upstream; default = 1 (preserves upstream). t14 sets to 50. |
| `omarchy.firewall.enable = false` is being phased out by t14's own `# Defense-in-depth: networking.firewall.enable = false` | Low | The double-disable is intentional. Don't touch. |
| `wayvnc` moved upstream: `pkgs.wayvnc` not in omarchy's overlay | Medium | Upstream must add it to `modules/packages.nix` (systemPackages) — verify path. |
| `mouse-wiggle.nix` `home.packages` not in HM-nixos integrated path | None | It's a per-host HM module; no change. |
| HM standalone `osConfig` workaround (flake.nix:269-285) becomes redundant if omarchy stops reading `osConfig.omarchy` | None | Document but don't remove until upstream confirms. |

### Migration order (recommend)

To keep each step bisectable + revertible, follow this order:

1. **Phase 1 — Add new options to omarchy-nix (upstream).**
   - Add `omarchy.hyprlock.{size,font_family,placeholder_text,fingerprint}` to `config.nix` and consume in `hyprlock.nix` with `mkDefault`.
   - Add `omarchy.hyprland.gaps_in/out`, `omarchy.hyprland.decoration.*`, `omarchy.hyprland.initial_workspace_tracking` to `config.nix` + `looknfeel.nix`.
   - Add `omarchy.hyprsunset.schedule` + default in `hyprsunset.nix`.
   - Add `omarchy.hypridle.lock_delay` in `hypridle.nix`.
   - Add `omarchy.gtk.iconTheme` in `default.nix`.
   - Bump omarchy-nix input in this repo's `flake.nix` to the new commit.
   - Run `nix flake check --no-build` to verify nothing breaks.

2. **Phase 2 — Convert t14 local overrides to opt-in `omarchy.*` declarations.**
   - In `hosts/t14/default.nix` `omarchy = { … }`, add the new opt-ins (e.g. `hyprlock.font_family = "Source Sans Pro"`, `hyprland.gaps_in = 0`, etc.).
   - In `hosts/t14/home/omarchy.nix`, drop the `mkForce` blocks (hypridle, gtk.iconTheme, etc.) since the new opt-ins live in the NixOS-level `omarchy.*` block (which HM propagates via the osConfig bridge).
   - Run `nix flake check --no-build` and `nixos-build dry` to verify.

3. **Phase 3 — Delete pure-duplicate t14 files.**
   - DELETE `hosts/t14/home/hypr/xdph.nix` (upstream has byte-identical).
   - DELETE `hosts/t14/home/scripts/window-switcher.sh` (use `omarchy-launch-walker -m windows`).
   - DELETE `hosts/t14/home/scripts/monitor-hotplug-handler.sh` (superseded by `omarchy-hyprland-monitor-watch`).
   - DELETE `hosts/t14/home/hypr/autostart.nix` (empty).
   - DELETE `hosts/t14/home/ghostty.nix` (no delta from shared file).
   - DELETE the `home.file` script drops in `hosts/t14/home/default.nix:39-80` (no longer needed).
   - Run `nix flake check --no-build` to verify.

4. **Phase 4 — Trim `hosts/t14/home/default.nix` waybar override.**
   - Keep only the iwd-wifi indicator (`home.file."indicators/iwd-wifi.sh"`) and the `modules-right` change.
   - Or move the iwd-wifi indicator to omarchy's `config/waybar/indicators/iwd-wifi.sh` as a t14/standalone-iwd add-on.
   - Run `nixos-build dry`.

5. **Phase 5 — Optional: wayvnc as upstream module.**
   - Create `modules/home-manager/wayvnc.nix` + `modules/nixos/wayvnc.nix` in omarchy-nix.
   - Add `omarchy.wayvnc.enable = true; omarchy.wayvnc.port = 5900;` to `hosts/t14/default.nix`.
   - Delete `hosts/t14/home/wayvnc/default.nix` and the `programs.wayvnc.enable` line in `hosts/t14/default.nix:94`.
   - Bump omarchy-nix input again.
   - Run `nix flake check --no-build` and `nixos-build dry`.

6. **Phase 6 — Audit remaining `hypr/{bindings,input,monitors,looknfeel}.nix`.**
   - `bindings.nix`: delete all 5 if duplicates; keep only t14-specific extras.
   - `input.nix`: trim to `mkForce kb_layout` (es,latam) + maybe gesture override.
   - `monitors.nix`: keep desc-based monitor list; delete lid-switch exec-once (use upstream's binding).
   - `looknfeel.nix`: should be ~5 lines (or zero if all options are now upstream).
   - `hyprsunset.nix`: should be ~5 lines (`omarchy.hyprsunset.schedule = [ … ];`).
   - `hyprlock.nix`: should be 0 lines (use upstream).

### Worst-case blast radius

If everything goes wrong, the rollback is `git revert` of each phase
separately. The change is **purely deletions + `mkForce` → `omarchy.*` opt-in
moves** — no new logic, no new options in *this* repo. The only way a phase
breaks t14 is if upstream omarchy-nix introduced a regression in a new
`omarchy.*` option, which is why each phase ends with `nix flake check
--no-build` and (for phases 2-5) `nixos-build dry`.

## Key Learnings

1. **The pattern is well-established and proven.** Three prior refactors
   (`restore-omarchy-hyprland-ownership`, `omarchy-theme-glats-upstream`,
   `nixos-host-pattern-refactor`) followed the same template: push to
   upstream, simplify local. This is the fourth — and the largest —
   application of that pattern.

2. **Upstream is 90% of the way there.** The hard part (writing reusable
   options that handle edge cases) is largely done. What's missing is
   mostly **opt-in granularity** — exposing currently-hardcoded values
   (gap sizes, decoration, hyprlock font, etc.) as `omarchy.*` options with
   sane defaults. Mechanical work, not design work.

3. **The t14 omarchy.nix file has 175 lines of which 130 are `mkForce`
   overrides of upstream defaults.** This is the single biggest "win" of
   this refactor: turning overrides into opt-ins means *no override* is
   needed when the value matches the new default.

4. **The `home-linux/{ghostty,kitty}.nix` `mkForce` pattern is fragile.**
   It works today (and is the documented pattern from the btop refactor)
   but it means **t14 doesn't actually use omarchy's ghostty/kitty
   config** — it uses the shared base. This is fine, but it's a hidden
   coupling. If a future user wants to consume omarchy's ghostty on
   rog/thinkcentre, they'll need a different mechanism.

5. **The `osConfig` workaround in `flake.nix:269-285` is the single
   biggest blocker for "t14 as pure consumer".** It exists because
   omarchy-nix's HM module reads `osConfig.omarchy` via
   `pushDownProperties.mapAttrs`, which forces eval before `mkIf` can
   short-circuit. **Upstream fix would be to use `attr or default` in
   the module function** — this is a one-line change in
   `omarchy-nix:flake.nix:55`. If we can land that upstream in the same
   change, the entire `_module.args.osConfig = mkForce { omarchy = {}; };`
   workaround can be deleted, and t14's `homeConfigurations.t14` entry
   collapses to 5 lines.

6. **wayvnc is the only t14-specific service not in omarchy.** It would
   be the first "new upstream module" added by this refactor. It
   consumes a Niri-era pattern (VNC over Wayland via wlroots
   screencopy) and is generic enough to be useful to other omarchy
   users (gamers, screen-sharers, headless test rigs).

7. **t14 has 5 keybindings that ALL duplicate upstream.** The simplest
   part of this refactor: delete `bindings.nix` entirely. The user's
   lid-switch is already covered by upstream's `omarchy-hyprland-monitor-internal toggle`
   binding (SUPER CTRL DELETE). The `window-switcher.sh` script is
   already covered by `omarchy-launch-walker -m windows`.

8. **The `monitor-hotplug-handler.sh` script is already dead.** The
   autostart.nix file is empty and contains a long comment explaining
   why. The script itself can be deleted — omarchy's
   `omarchy-hyprland-monitor-watch` daemon already does the same
   detection. The t14-specific desc:-based monitor list in
   `monitors.nix` is the only thing that *should* stay.

9. **The hyprlock overrides are mostly cosmetic.** Most of
   `hosts/t14/home/hypr/hyprlock.nix` is overriding upstream's
   `input-field.size` from `600, 100` to `650, 100`, `font_family`
   from `CaskaydiaMono Nerd Font` to `Source Sans Pro`, and
   `placeholder_text` from `"   Enter Password  "` to `"Enter Password"`.
   None of these are t14-specific — they're user-preference. The
   cleanest path is upstream `omarchy.hyprlock.*` options with the
   upstream defaults as t14's opt-in.

10. **Cascading effect on `home-linux/shared-modules.nix`.** Once
    `omarchy-nix` owns ghostty/kitty/tmux, the `mkForce` blocks in
    `home-linux/{ghostty,kitty,tmux}.nix` are unnecessary. They
    exist today to override omarchy's defaults. If omarchy's
    defaults are *the* defaults (no override needed on rog/thinkcentre),
    the shared files can be simplified — and that simplifies
    the `home-linux/` tree in the same change. This is a
    follow-on simplification, not strictly in scope, but
    worth flagging.

11. **DON'T delete `home.activation.copyScreensaverTxt` from t14.**
    It runs `linkGeneration` instead of upstream's `writeBoundary`
    because of a real bug (logo.txt doesn't exist on first
    activation). The fix is to push the same `linkAfter` upstream
    as the new default. If we don't, t14 re-introduces the local
    override.

12. **NerdFont icon U+E900 must remain stable.** The waybar
    `custom/omarchy` module uses `<span font='omarchy'>\ue900</span>`
    — this is a non-Nix-encodable character (per upstream's comment).
    Any path that goes through Nix's JSON encoder (i.e., using
    `pkgs.formats.json.generate`) will strip it. The current t14
    config uses `pkgs.formats.json` for waybar which means **the
    omarchy icon is already being filtered!** This is a hidden
    bug. Upstream's `waybar.nix` solves this by deploying the
    raw config file (not via `formats.json`). If t14 switches to
    upstream's waybar, this is automatically fixed.
