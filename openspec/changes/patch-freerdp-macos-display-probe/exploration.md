## Exploration: patch-freerdp-macos-display-probe

### Current State
- macm5 RDP launchers: `darwin/home/remote-desktop.nix` (C launcher -> `sdl-freerdp`, FreeRDP 3.30.0, SDL 3.4.10; verified via `nix eval`). `overlays/darwin.nix:16-38` already overrides `sdl3` (clipboard patch) and `freerdp` (VideoToolbox, uses patched sdl3) -> freerdp is built locally. Args include `/workarea /w:1680 /h:1050 /smart-sizing`.
- Launcher currently sets `SDL_VIDEO_MAC_FULLSCREEN_SPACES=0` only when `CGGetActiveDisplayList` count > 1 (uncommitted; `remote-desktop.nix:~89-96`; commit 944fbb7 set it unconditionally). Cost: green button no longer enters a native fullscreen Space on multi-display, which the user wants.
- Root cause (verified, A/B-measured earlier): `sdl_freerdp.cpp:700` -> `SdlContext::detectDisplays()` -> `SdlWindow::query(id)` per display -> `createDummy(id)` (3.30.0 `sdl_window.cpp:581-616`) makes a 64x64 borderless visible window, moves it to the display origin, calls `SDL_SetWindowFullscreen(window,true)` (`:613`), creates a renderer, `SDL_SyncWindow`, reads values, destroys. With Spaces on (SDL default; hint read once at video init), each probe = native fullscreen Space (~0.65s/display). Size flags irrelevant.
- `createDummy` is byte-identical on FreeRDP master (`sdl_window.cpp:756-792`) -> not fixed in any release.
- What probe values feed: `query(window,...)` (`:366-413`) -> `rdpMonitor` x/y (SDL_GetWindowPosition), width/height (SDL_GetWindowSizeInPixels), `desktopScaleFactor = round(SDL_GetWindowDisplayScale*100)`. With `/workarea`, `sdl_apply_display_properties` (`sdl_monitor.cpp:175-198`) copies the lowest-id display's probed monitor (x=y=0, primary) into `MonitorDefArray`; max-size logic uses `SDL_GetDisplayUsableBounds` (`sdl_monitor.cpp:140-146`), not the probe. Whether probed w/h/scale influence the real session when `/w /h` are given is NOT verified.
- `openspec/changes/improve-macm5-remote-launchers/` is unrelated (bundle naming/deploy, scroll direction); only shares the unchanged freerdp overlay. Prior engram #197/#198 (`macm5-remote-desktop-window-mode`) is the predecessor of this change; its Approach 3 ("patch FreeRDP, not upstream") is superseded by the finding below.

### Research findings (verified unless marked)
1. **Upstream has an open fix: FreeRDP PR #13564** "[client,sdl] query macOS display geometry without a probe window" (author oceanzhang88, opened 2026-09-30, OPEN/unmerged, no maintainer review yet, only bot + author comments): https://github.com/FreeRDP/FreeRDP/pull/13564 . Commit `dc5c7eeef2bb92f1b8cd767d278ec1c99a6534d2`; patch fetchable at `https://github.com/FreeRDP/FreeRDP/commit/dc5c7eeef2bb92f1b8cd767d278ec1c99a6534d2.patch` (HTTP 200, 11.6 KB). Based on master a8f1b46.
   - Diagnoses exactly our problem; on cocoa driver only (runtime `SDL_GetCurrentVideoDriver()=="cocoa"`, `#if __APPLE__`), `SdlWindow::query/rect(SDL_DisplayID)` compute geometry with NO window: `SDL_GetDisplayBounds` (pos), `SDL_GetDesktopDisplayMode(id)->pixel_density` x bounds (pixel size), `pixel_density x SDL_GetDisplayContentScale` (desktopScaleFactor). Other drivers keep the probe window.
   - Preserves Spaces-on semantic: new `sdl_macos.mm` (AppKit `safeAreaInsets`) trims the notch menu-bar strip from the top when the hint is on. Author's table (macOS 27, SDL 3.4.16, 2 displays): Spaces on: built-in `0,33 3456x2168`, Spaces off `0,0 3456x2234`; externals equal; 0 windows / 0 Space changes after patch vs 6 / 6 before; `detectDisplays()` 1362ms -> 2ms; per-field monitor values identical before vs after in both modes. Session against a real server tested once (windowed `/size /smart-sizing`); `/f`, `/multimon`, dynamic resolution untested.
   - Applicability to 3.30.0 (dry-run `patch -p1` against raw 3.30.0 files, scratch dir, removed): `sdl_window.cpp` hunks and new `sdl_macos.{hpp,mm}` apply; `CMakeLists.txt` hunk 1 (SRCS list, context has `sdl_x11.cpp` absent in 3.30.0) FAILS, hunk 2 (AppKit/CoreGraphics link) applies. So: fetchpatch with `excludes = [ "client/SDL/SDL3/CMakeLists.txt" ]` + a tiny local patch/`postPatch` adding `sdl_macos.hpp sdl_macos.mm` to `set(SRCS` (3.30.0 `CMakeLists.txt:26-50`) and the Apple link block. Compilation of `.mm` under the project's languages is NOT verified on our build (author built 3.32.1 via Homebrew).
   - Related: earlier PR #12615 (closed, rejected by maintainer akallabeth 2026-04-16: "there is no SDL API to query these settings from a display" — wlroots/all-platform variant): https://github.com/FreeRDP/FreeRDP/pull/12615 ; contributor cited SDL#15397 (Kontrabant: desktop display mode `pixel_density` is the best available per-display value). Issue about `FREERDP_WLROOTS_HACK` not triggering with the non-fullscreen dummy window (3.30.0, Hyprland) also found via `createDummy` search (wlroots-only, not macOS). Searches for "macOS fullscreen spaces", "black window multiple monitors", "detectDisplays" returned no issue other than #13564.
2. **nixpkgs**: `nixos-26.05` branch now has freerdp 3.31.1, master 3.32.1 (https://raw.githubusercontent.com/NixOS/nixpkgs/{nixos-26.05,master}/pkgs/by-name/fr/freerdp/package.nix); neither carries a macOS probe patch (no `patches`/`fetchpatch` hit). Our lock pins 3.30.0; a flake bump would change the base tree (re-check patch applies; PR says built against 3.32.1/master so CMake hunk 1 likely applies there).
3. **SDL**: no per-window Spaces control. `SDL_HINT_VIDEO_MAC_FULLSCREEN_SPACES` is global, read once at init ("must be set before creating a window"; SDL_hints.h release-3.4.x only matches that hint; the only cocoa create-props are `SDL_PROP_WINDOW_CREATE_COCOA_WINDOW/VIEW_POINTER`). SDL docs (context7 /libsdl-org/sdlwiki): `SDL_GetWindowPixelDensity` = pixel/window size ratio; `SDL_GetDisplayContentScale` = DPI-based expected scale; docs advise `SDL_GetWindowDisplayScale` post-creation.
4. **Own `SDL_SetWindowSize` patch soundness** (SDL release-3.4.x `SDL_cocoawindow.m`): no `constrainFrameRect` override exists in SDL (grep 0), borderless style at `:565-566`; `Cocoa_SetWindowSize` (`:2657-2691`) does `setFrame:` directly; `Cocoa_SetWindowPosition` (`:2606-2655`) `setFrameOrigin:`. AppKit default frame constraining applies mainly to titled windows (hypothesis, not confirmed against Apple docs here). Known divergence regardless: fullscreen-in-Space reports a notch-trimmed rect (`0,33 ...x2168` vs `0,0 ...x2234`), so a plain `SetWindowSize(display bounds)` would match the Spaces-OFF numbers, not what the code reports today with Spaces on (#13564 handles this explicitly). Also a visible borderless display-sized window still flashes per display (author: "each display flashes black for a moment" with hint off). Hidden-window (`SDL_PROP_WINDOW_CREATE_HIDDEN_BOOLEAN`) size reporting on Cocoa: not verified.

### Approaches
1. **Backport upstream PR #13564** (fetchpatch pinned to commit SHA, exclude CMakeLists, local CMake adapter) — window-free probing on cocoa.
   - Pros: no windows/Spaces/flash at all; upstream-authored and measured (identical monitor values before/after, incl. notch); keeps Spaces on; also fixes `SdlWindow::rect(SDL_DisplayID)`; easy to drop when merged/released.
   - Cons: PR open, unreviewed, single external author (AI-assisted per disclosure); adds AppKit `.mm` + CMake link changes (build risk on 3.30.0); needs CMake hunk adaptation and fetchpatch hash; maintainer previously rejected a broader variant.
   - Effort: Low-Medium.
2. **Own `SDL_SetWindowSize` patch in `createDummy` under `__APPLE__`** (original proposal).
   - Pros: 1-3 lines, no new files/CMake changes; probe stays window-based.
   - Cons: authored from scratch/untested; still shows a flashing borderless window per display; returns notch-untrimmed values (differs from current Spaces-on numbers); constrain/hidden behavior unverified; carries maintenance without upstream path.
   - Effort: Low (but verification-heavy).
3. **Hidden probe window** (`CREATE_HIDDEN true` + SetWindowSize/Fullscreen) — Fullscreen on hidden window on Cocoa may still trigger Space; unverified; same value-divergence issues. Low value.
4. **Compute rdpMonitor from display APIs without a window, own implementation** — same as #1 minus AppKit inset (loses notch trim -> desktop 66px taller than a Spaces-fullscreen window can show; matters only if `/f` used). Slightly simpler than #1 (no `.mm`/CMake), but reinvents #1.
   - Effort: Low-Medium.
5. **Status quo (env hint)** — keep conditional `SDL_VIDEO_MAC_FULLSCREEN_SPACES=0` (display-count > 1). Zero build cost; loses Space-fullscreen green button on multi-display (user rejects); probe still flashes black ~50ms/display.
6. **Wait for/bump to upstream release** — no release contains a fix; PR unmerged.

### Recommendation
Approach 1: carry #13564 as a pinned patch (commit SHA `dc5c7eee…`, exclude its CMakeLists hunk, add a minimal local `patches/freerdp/` CMake adapter registering `sdl_macos.{hpp,mm}` + AppKit/CoreGraphics link), then remove the launcher setenv so Spaces stay on. It is the only option that removes the windows entirely, preserves existing monitor values, and has an upstream exit path. Fall back to Approach 4/2 only if the `.mm` build fails on 3.30.0. Add a removal note ("drop once nixpkgs freerdp includes #13564").

Verification plan: (a) `nix fmt`, `nix eval .#darwinConfigurations.macm5.config.system.build.toplevel.drvPath`, build freerdp (`nix build` the overridden package); confirm CMake picks up `sdl_macos.mm`. (b) A/B probe timing with Spaces=1 against a closed localhost port (3 displays): gaps should drop from ~650ms to ms, no Space transitions. (c) `/log-level:DEBUG` per display before vs after: compare `monitor.x/y/width/height/desktopScaleFactor` (expect identical, incl. built-in `y` notch inset with Spaces on). (d) Real RDP session: windowed `/workarea /w /h /smart-sizing`, check initial size/scale, green button -> native Space fullscreen, `/list:monitor` unchanged. (e) Optional: `strings` check that launcher no longer sets the env var.

### Risks
- #13564 unmerged/unreviewed; may change (pin SHA, not PR ref, to keep the fetchpatch hash stable).
- 3.30.0 vs master drift: CMake hunk fails, compile of `.mm` unverified; possible other API differences (only `sdl_window.cpp` hunks verified by dry-run, not compiled).
- Window-free values assume cocoa `pixel_density`==backing scale and unconstrained fullscreen frame (author-verified on SDL 3.4.16; ours is 3.4.10 and macm5 hardware/macOS may differ, e.g. notch/menu-bar auto-hide untested upstream).
- Real-session effect of probed monitor values with `/workarea /w /h` unverified; compare logs before/after.
- Local rebuild required each freerdp-touching bump; patch must be dropped/re-checked at the 3.31+/3.32 bump.
- Do not use `FREERDP_WLROOTS_HACK`/other Linux paths; unchanged here.
