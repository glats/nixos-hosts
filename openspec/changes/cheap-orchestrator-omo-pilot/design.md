# Design: Cheap Orchestrator and OmO Pilot

## Technical Approach

Deliver four independently reversible stages: pin OpenCode 1.18.22, prove the five existing managed TypeScript plugins load, change the rog-selected orchestrator mapping, then add a default-off OmO Home Manager branch enabled only by rog. Nix remains authoritative; no OmO installer or migration command runs.

## Architecture Decisions

| Decision | Options / tradeoff | Choice and rationale |
|---|---|---|
| Binary pin | nixpkgs vs custom release derivation | Keep `pkgs/opencode/default.nix`; prefetch the four 1.18.22 release URLs with `nix-prefetch-url`, then convert with `nix hash convert --hash-algo sha256 --to sri`, matching its update script and prior bump. |
| OmO release and hash | Beta has newer docs; stable limits change risk | Pin npm `oh-my-opencode` **4.19.4**, the registry `latest` stable release on 2026-09-10 (not 5.x beta). Add its tarball SRI to `node-modules.json` using the existing `nix-prefetch-url` plus `nix hash to-sri --type sha256` precedent. Register its documented plugin alias `oh-my-openagent`. |
| Conditional ownership | Imperative installer vs Home Manager | Add `home.opencode.omo.enable` as a boolean defaulting false beside `activeProviderName`; expose `omo = cfg.omo.enable` in `plugins.nix`'s computed `activePlugins`. `runtime-config.nix` appends the npm plugin with `lib.optionals` and conditionally adds a `home.file` source generated by `pkgs.writeText`. Home Manager removes its symlink when disabled; unlike the explicit historical `background-agents.ts` cleanup, no unmanaged `~/.omo` runtime state is deleted. |
| Category routing | Duplicate profile tables vs active-tier lookup | Import `providers.nix` with `cfg.activeProviderName` in `runtime-config.nix`, then call existing `getModelForPhase`: `quick` uses `sdd-apply` (light/volume), while `deep` and `ultrabrain` use `sdd-design` (reasoning/judgment). Thus profile changes propagate without a second mapping table. |
| Telemetry boundary | Config-only vs defense in depth | Put `telemetry = false` inside `[opencode]` and conditionally set `home.sessionVariables.OMO_DISABLE_POSTHOG = "1"` in `shared/opencode.nix`, following the existing `RTK_TELEMETRY_DISABLED` environment pattern. |

## Data Flow

`activeProviderName → providers.activeProvider → getModelForPhase → omo.jsonc categories`

`omo.enable → plugin array + ~/.omo/omo.jsonc + session variable`

The exact generated document is `{ "$schema": "…/dev/assets/omo.schema.json", "[opencode]": { "disabled_mcps": ["websearch","context7","grep_app"], "disabled_hooks": ["directory-agents-injector","rules-injector"], "telemetry": false, "team_mode": { "enabled": false }, "categories": { "quick": { "model": … }, "deep": { "model": … }, "ultrabrain": { "model": … } } } }`. Omitting `lsp` from `disabled_mcps` retains it. These keys are confirmed by the dev reference and stable 4.19.4 schema.

## Interfaces / Contracts

`home.opencode.omo.enable : bool = false`. Enabled means all three host-visible artifacts exist; disabled means no plugin entry, managed `~/.omo/omo.jsonc`, or OmO environment variable. The npm closure may remain globally built under the existing package architecture but is inert without registration.

## Testing Strategy

| Stage | Gate |
|---|---|
| Binary | Build/evaluate all four platforms; on rog run `opencode --version` and `opencode debug config --print-logs --log-level DEBUG`, requiring 1.18.22 and no load error for each of the five named plugins. |
| Routing | Evaluate generated rog agent JSON; run delegation, retry, gate, no-early-exit, and measured-cost comparison. |
| OmO | `nix eval --raw .#homeConfigurations.<host>.config.home.file.<quoted-path>.source` plus JSON inspection: rog has exact policy/models; thinkcentre, t14, and mact2 lack all OmO artifacts. Run the pinned `node_modules/oh-my-opencode/bin/oh-my-opencode.js doctor --verbose` on rog. |
| Repository | `format-nix && nix flake check --no-build`. |

## Threat Matrix

| Boundary | Applicability | Safe / failure behavior | Planned RED test |
|---|---|---|---|
| TypeScript plugin process integration | Applicable | Default-off hosts never load OmO; enabled host fails acceptance on load/schema errors. | Compare host evaluations; invoke debug config and doctor with pinned runtime. |
| npm supply chain | Applicable | Exact stable version and SRI admit known bytes; hash mismatch fails the Nix build. | Build with the pin and prove a deliberately wrong hash is rejected. |

## Migration / Rollout

Stage failures stop progression. Restore the 1.18.18 hash block, restore the single GLM line, or remove rog's enable flag respectively. Disabling OmO preserves unmanaged `~/.omo` runtime directories.

## Open Questions

None. Exact hash values are apply-time derived outputs, not design blockers.
