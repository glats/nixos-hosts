# Design: nautilus-dark-mode-t14

## Technical Approach

Fix Nautilus dark mode on t14 (Hyprland) by ensuring xdg-desktop-portal exports the Settings interface. Three changes in `hosts/t14/default.nix`: remove redundant `xdg.portal.extraPortals`, deploy a corrected `gtk.portal` file via `environment.etc`, and add explicit portal config routing Settings to the gtk implementation.

## Architecture Decisions

### Decision: Use `environment.etc` for gtk.portal override

| Option | Tradeoff | Decision |
|--------|----------|----------|
| `environment.etc` (system-level) | Declarative, survives rebuilds, applies system-wide | **Chosen** |
| `~/.local/share/xdg-desktop-portal/portals/gtk.portal` (user-level) | Fragile, incomplete (missing DBusName/Interfaces), wrong directory semantics | Rejected |

The user's manual override was incomplete — missing `DBusName` and `Interfaces` fields — and placed at the wrong XDG_DATA path. `environment.etc` places the file at `/etc/xdg/xdg-desktop-portal/portals/gtk.portal` (symlinked from Nix store), which takes precedence over `/run/current-system/sw/share`.

### Decision: Use `lib.mkForce` for portal config

| Option | Tradeoff | Decision |
|--------|----------|----------|
| `lib.mkForce` | Fights omarchy-nix refactors; intentional — we need explicit `Settings=gtk` | **Chosen** |
| Plain attribute | Could be silently overridden by upstream changes | Rejected |

omarchy-nix only sets `default`, not `Settings`. `mkForce` ensures our explicit mapping survives any upstream refactors.

### Decision: Keep `UseIn=gnome;hyprland` in gtk.portal

| Option | Tradeoff | Decision |
|--------|----------|----------|
| `UseIn=gnome;hyprland` | Preserves GNOME compatibility if config is shared across hosts | **Chosen** |
| `UseIn=hyprland` only | Breaks GNOME if this config is ever shared | Rejected |

### Decision: Single-file change (hosts/t14/default.nix only)

| Option | Tradeoff | Decision |
|--------|----------|----------|
| Single file | Keeps fix scoped to affected host; minimal diff | **Chosen** |
| Multi-file (new module) | Over-engineered for a host-specific fix | Rejected |

## Data Flow

```
Nautilus (libadwaita)
  → queries org.freedesktop.portal.Desktop /org/freedesktop/portal/desktop
  → org.freedesktop.portal.Settings.ReadAll(["org.freedesktop.appearance"])
     ↓
xdg-desktop-portal (main daemon)
  → looks up "org.freedesktop.impl.portal.Settings" in hyprland-portals.conf
  → finds "gtk"
  → proxies to org.freedesktop.impl.portal.desktop.gtk
     ↓
xdg-desktop-portal-gtk
  → reads dconf org.gnome.desktop.interface color-scheme
  → returns uint32 1 (prefer-dark)
     ↓
libadwaita receives color-scheme=1 → AdwStyleManager → dark mode
```

## File Changes

| File | Action | Description |
|------|--------|-------------|
| `hosts/t14/default.nix` | Modify | (1) Remove `xdg.portal.extraPortals` line, (2) Add `environment.etc` block for gtk.portal with `UseIn=gnome;hyprland`, (3) Add `xdg.portal.config.hyprland` with `Settings=gtk` |

No new files. No deleted files. One modified file.

## Interfaces / Contracts

### gtk.portal file content

```ini
[portal]
DBusName=org.freedesktop.impl.portal.desktop.gtk
Interfaces=org.freedesktop.impl.portal.FileChooser;org.freedesktop.impl.portal.AppChooser;org.freedesktop.impl.portal.Print;org.freedesktop.impl.portal.Notification;org.freedesktop.impl.portal.Inhibit;org.freedesktop.impl.portal.Access;org.freedesktop.impl.portal.Account;org.freedesktop.impl.portal.Email;org.freedesktop.impl.portal.DynamicLauncher;org.freedesktop.impl.portal.Lockdown;org.freedesktop.impl.portal.Settings;org.freedesktop.impl.portal.Wallpaper;
UseIn=gnome;hyprland
```

### hyprland-portals.conf (generated by NixOS module)

```ini
[preferred]
default=hyprland;gtk
org.freedesktop.impl.portal.Settings=gtk
```

## Testing Strategy

| Layer | What to Test | Approach |
|-------|-------------|----------|
| Build | NixOS configuration evaluates | `nix flake check --no-build` |
| Deploy | gtk.portal file is created at `/etc/xdg/xdg-desktop-portal/portals/gtk.portal` | Verify path exists after rebuild |
| Integration | Portal exports Settings interface | `dbus-send --session --print-reply --dest=org.freedesktop.portal.Desktop /org/freedesktop/portal/desktop org.freedesktop.portal.Settings.ReadAll array:string:"org.freedesktop.appearance"` — expect `color-scheme = uint32 1` |
| E2E | Nautilus renders in dark mode | Launch Nautilus, confirm dark theme |

## Migration / Rollout

1. Apply change: `nixos-build switch` on t14
2. User post-rebuild: `rm ~/.local/share/xdg-desktop-portal/portals/gtk.portal` (delete stale user-level override)
3. Re-login (portal user service restarts at session boundary, picks up new config)

No data migration. No feature flags. No phased rollout.

## Open Questions

None. The exploration phase confirmed all root causes and the design addresses them directly.
