# Exploration: t14-hdm-migration-v3 — post-deploy fix

## Symptoms

1. AOC 24P1W1 monitor NOT rotated (transform not applied)
2. Hyprland showing an error
3. `~/.config/hypr/config.d/99_autogenerated-monitors.conf` does NOT exist
4. `~/.config/hyprdynamicmonitors/hyprconfigs/` does NOT exist

## Diagnosis Results

| Test | Result | Finding |
|------|--------|---------|
| `ls ~/.config/hyprdynamicmonitors/` | Only `config.toml` + `config.toml.backup` | No `hyprconfigs/` subdirectory |
| `ls ~/.config/hyprdynamicmonitors/hyprconfigs/` | No such file or directory | Confirmed missing |
| `ls ~/.config/hyprconfigs/` | 5 `.conf` files present | **Files deployed to WRONG path** |
| HDM manual run | `Fatal: config file .../hyprconfigs/docked-lid-open.conf not found` | HDM looks in `~/.config/hyprdynamicmonitors/hyprconfigs/` |
| `systemctl --user status hyprdynamicmonitors-prepare` | Failed (exit-code 1) | Prepare service also fails with same error |
| Active HM files gen `7pk...` | Has `hyprconfigs/` at `.config/` level, NOT under `hyprdynamicmonitors/` | Files deployed one level too high |
| Older HM files gen `07y4...` | Has `hyprdynamicmonitors/hyprconfigs -> ...hm_hyprconfigs` (directory symlink) | Older deployment was correct |

## Root Cause

**The `extraFiles` keys in `hosts/t14/home/default.nix` are missing the `hyprdynamicmonitors/` prefix.**

The HDM HM module deploys extraFiles via:
```nix
name = "${config.home.homeDirectory}/.config/${k}"
```

Where `k` is the key from `extraFiles`. So:

| Key (actual) | Deployed to | HDM expects at |
|--------------|-------------|----------------|
| `"hyprconfigs/docked-lid-open.conf"` | `~/.config/hyprconfigs/docked-lid-open.conf` | `~/.config/hyprdynamicmonitors/hyprconfigs/docked-lid-open.conf` |
| `"hyprdynamicmonitors/hyprconfigs"` | `~/.config/hyprdynamicmonitors/hyprconfigs` (directory symlink) | ✅ CORRECT |

The config.toml references files with relative paths like `hyprconfigs/docked-lid-open.conf`. HDM resolves these relative to the config file's directory (`~/.config/hyprdynamicmonitors/`), so it expects them at `~/.config/hyprdynamicmonitors/hyprconfigs/...`.

The files DO exist (all 5 `.conf`), just at the wrong level: `~/.config/hyprconfigs/` instead of `~/.config/hyprdynamicmonitors/hyprconfigs/`.

### Design vs Implementation Gap

The v3 **design** (line 34, design.md) specified:
```nix
extraFiles = { "hyprdynamicmonitors/hyprconfigs" = ./hdm/hyprconfigs; }
```
— a single entry deploying the whole directory. ✅

The v3 **implementation** (hosts/t14/home/default.nix) wrote:
```nix
extraFiles = {
  "hyprconfigs/docked-lid-open.conf" = ../hdm/hyprconfigs/docked-lid-open.conf;
  "hyprconfigs/docked-lid-closed.conf" = ../hdm/hyprconfigs/docked-lid-closed.conf;
  "hyprconfigs/undocked-lid-open.conf" = ../hdm/hyprconfigs/undocked-lid-open.conf;
  "hyprconfigs/undocked-lid-closed.conf" = ../hdm/hyprconfigs/undocked-lid-closed.conf;
  "hyprconfigs/fallback.conf" = ../hdm/hyprconfigs/fallback.conf;
};
```
— 5 individual file entries, all missing the `hyprdynamicmonitors/` prefix. ❌

### Why This Broke

1. The `configFile` option (line 39) deploys `config.toml` correctly to `~/.config/hyprdynamicmonitors/` because the module uses `configPath` (default: `~/.config/hyprdynamicmonitors/config.toml`) for the toml entry, but a different formula for extraFiles.
2. The prepare service fails because HDM can't find the hyprconfigs at the expected path during boot-time cleanup.
3. The main service also fails for the same reason — profile matching finds the config.toml but can't load any profile's config_file.

## Recommended Fix

**Option A: Single directory entry (matches design — recommended)**

```nix
extraFiles = {
  "hyprdynamicmonitors/hyprconfigs" = ../hdm/hyprconfigs;
};
```

- One line, one store path
- Deploys a directory symlink at `~/.config/hyprdynamicmonitors/hyprconfigs` → nix store copy
- `hyprconfigs.extraFiles` type is `attrsOf types.path` — directory path is valid
- Matches the v3 design exactly
- Works because HDM follows symlinks when reading config_files

**Option B: Individual files with full prefix (more explicit)**

```nix
extraFiles = {
  "hyprdynamicmonitors/hyprconfigs/docked-lid-open.conf" = ../hdm/hyprconfigs/docked-lid-open.conf;
  "hyprdynamicmonitors/hyprconfigs/docked-lid-closed.conf" = ../hdm/hyprconfigs/docked-lid-closed.conf;
  "hyprdynamicmonitors/hyprconfigs/undocked-lid-open.conf" = ../hdm/hyprconfigs/undocked-lid-open.conf;
  "hyprdynamicmonitors/hyprconfigs/undocked-lid-closed.conf" = ../hdm/hyprconfigs/undocked-lid-closed.conf;
  "hyprdynamicmonitors/hyprconfigs/fallback.conf" = ../hdm/hyprconfigs/fallback.conf;
};
```

- More lines but more explicit
- Each file gets its own symlink
- Safer if individual files need different permissions later

**Recommendation: Option A** — simpler, matches the design, and the old working generations used this exact pattern (directory symlink). One-line change.

## Risk Assessment

| Risk | Likelihood | Impact |
|------|-----------|--------|
| Fix doesn't match — files still at wrong path | Low (the math is straightforward) | High |
| `extraFiles` doesn't accept directory paths | Low (type is `attrsOf types.path`, directory is a valid path) | Medium (fallback to Option B) |
| Home Manager activation fails due to stale `~/.config/hyprconfigs/` | Low (HM manages its own files; `hyprconfigs/` was HM-deployed, will be replaced) | Low |

## Ready for Apply

**Yes.** The fix is a one-line change (Option A) or a key-prefix update (Option B). No structural changes needed. No new Nix evaluation issues — the design already validated that `extraFiles` with a directory source works. The old deployments used exactly this pattern successfully.
