# Delta for t14-monitor-layout

## ADDED Requirements

### Requirement: HDM Daemon Startup

The system MUST start HDM via its NixOS module before Hyprland parses monitor config. HDM's `prepare` service MUST run `Before=graphical-session-pre.target`. The HDM runtime service MUST run `After=graphical-session.target` with `PartOf=graphical-session.target`. HDM MUST receive `--enable-lid-events` to subscribe to UPower lid events via D-Bus.

#### Scenario: HDM starts before Hyprland

- GIVEN t14 boots with Hyprland session
- WHEN systemd starts user services
- THEN `hyprdynamicmonitors-prepare.service` runs before graphical-session-pre
- AND `hyprdynamicmonitors.service` starts after graphical-session
- AND HDM generates `99_autogenerated-monitors.conf` before Hyprland reads it

### Requirement: monitors.nix Sources HDM Output

The `monitors.nix` file MUST source HDM's generated config via `source = ~/.config/hypr/config.d/99_autogenerated-monitors.conf`. The file MUST NOT contain any `monitor=` directives for eDP-1 or external monitors. The file MUST retain `mkWorkspaceRules` and `env = ["GDK_SCALE,1"]`.

#### Scenario: HDM output is sourced correctly

- GIVEN HDM has generated `99_autogenerated-monitors.conf`
- WHEN Hyprland loads the t14 config
- THEN monitor directives come from HDM's generated file
- AND workspace rules come from monitors.nix Nix expression
- AND GDK_SCALE=1 is set as environment variable

### Requirement: Omarchy Lid Switch Stays Disabled

The system MUST preserve `omarchy.hyprland.lidSwitch.enable = false` to prevent omarchy's `bindl` from double-firing lid events alongside HDM's UPower handler.

#### Scenario: No double lid handling

- GIVEN HDM is running with `--enable-lid-events`
- WHEN the user closes the lid
- THEN only HDM processes the lid event
- AND omarchy's bindl does NOT fire

## MODIFIED Requirements

### Requirement: Workspace Distribution

Workspace rules MUST be defined in Nix using cyclic mod-3 distribution across 20 workspaces, independent of monitor positioning. Rules MUST use `monitor:desc:{descriptor}` syntax with `default` and `persistent` flags. Distribution: AOC 24P1W1 gets ws 1,4,7,10,13,16,19; Lenovo G24-10 gets ws 2,5,8,11,14,17,20; AOC 2470W gets ws 3,6,9,12,15,18.
(Previously: Workspace rules were in the same `monitors.nix` file alongside static `monitor=` blocks and `# hyprlang if` conditionals — now they are the sole content of monitors.nix alongside GDK_SCALE and the HDM source directive)

#### Scenario: Cyclic workspace distribution

- GIVEN Hyprland session is running with 3 externals connected
- WHEN workspace 1 is created
- THEN it lands on `monitor:desc:AOC 24P1W1 OTNQ4HA000101` with `default:true,persistent:true`

#### Scenario: Workspace 5 distribution

- GIVEN Hyprland session is running with 3 externals connected
- WHEN workspace 5 is created
- THEN it lands on `monitor:desc:Lenovo Group Limited LEN G24-10 U5B4GWF1` with `default:false,persistent:true`

#### Scenario: GDK scale preserved

- GIVEN Hyprland session is running
- WHEN a GTK application starts
- THEN GDK_SCALE=1 prevents automatic HiDPI scaling

## REMOVED Requirements

### Requirement: Polling Daemon (CAP-DAEMON)

(Reason: Replaced by HDM's event-driven daemon subscribing to Hyprland socket2 and UPower — eliminates 2s polling lag and `/proc/acpi` reads)
(Migration: `hyprdynamicmonitors.service` handles all monitor positioning via TOML profiles)

### Requirement: Settings Persistence (CAP-SETTINGS)

(Reason: HDM manages state internally — no writable `settings.conf` or `$ENABLE_LAPTOP` variable needed)
(Migration: `home.activation.seedHyprSettings` and `settings.conf` file are deleted)

### Requirement: Hyprlang Conditionals and Lid Bindls (CAP-CONDITIONAL, CAP-LIDSWITCH)

(Reason: HDM profiles with `lid_state` conditions replace all `# hyprlang if ENABLE_LAPTOP` blocks and lid-switch `bindl` directives)
(Migration: HDM's `99_autogenerated-monitors.conf` provides the correct monitor directives per state)

### Requirement: udev-settle Drop-in

(Reason: HDM has internal retry logic and its `prepare` service handles startup ordering — `udevadm settle` is no longer needed)
(Migration: None — the `xdg.configFile` drop-in is simply deleted)
