# POSTMORTEM: hyprdynamicmonitors-migration-v1 (FAILED)

**Archived**: 2026-06-30
**Status**: FAILED — 6 critical bugs discovered during implementation
**Sessions**: 1 session, ~4 hours, 8 deploy attempts, all failed
**Supersedes**: `FAILED-2026-06-29-abri-el-lid-black-screen`

---

## What We Were Trying To Do

Replace the T14's 3-layer ~290-line custom monitor stack (polling bash daemon +
hyprlang conditionals + 300-char bindls + settings.conf) with HyprDynamicMonitors
(HDM v1.4.0), a Go daemon in nixpkgs with native Hyprland IPC, UPower lid events,
and TOML profile configuration.

## The 6 Bugs That Killed It

### BUG 1 — Tilde not expanded in Hyprland source directive
```
source = ~/.config/hypr/config.d/99_autogenerated-monitors.conf  ← FAILS
```
Hyprland does NOT expand `~` in `source` directives. Treated as literal path.
**Fix**: Use absolute path: `/home/glats/.config/hypr/...`
**Prevention**: NEVER use `~` in Hyprland config paths. Always use `config.home.homeDirectory`.

### BUG 2 — home.file clobber conflict with HDM
`home.file` deploys a Nix store symlink. HDM writes the generated config to the same
path at runtime. On the next home-manager activation, HM refuses to overwrite the
existing file: `"would be clobbered"`.
**Fix**: Use `home.activation` with `[ ! -f "$file" ]` guard — creates stub only if
HDM hasn't already created the file.
**Prevention**: Never use `home.file` for paths that runtime daemons write to.

### BUG 3 — Profile required_monitors used desc: instead of connector names
```toml
[[profiles.docked.conditions.required_monitors]]
name = "desc:AOC 24P1W1 OTNQ4HA000101"   ← NEVER MATCHES
```
HDM matches monitor conditions by Hyprland connector name (e.g., "DP-5"), NOT by
the `desc:` identifier. As a result, no profile ever matched and the system fell
through to the auto-position fallback — losing portrait rotation, dead-zone y=420,
and the entire custom layout.
**Fix**: Use connector names ("DP-5"), OR use `description` + `match_description_using_regex`.
**Prevention**: Check `hyprctl monitors -j` on the target system to see actual connector
names. Connector names can change across kernel updates (DP-3/4/5 became DP-6/7/8).

### BUG 4 — Fallback profile syntax
```toml
[profiles.fallback]        ← Treated as REGULAR profile, always matches!
```
HDM's dedicated fallback syntax is `[fallback_profile]`, NOT `[profiles.fallback]`.
A `[profiles.*]` entry with no conditions matches every state and can outscore
higher-specificity docked/undocked profiles.
**Fix**: Use `[fallback_profile]` (only applied when NO other profile matches).
**Prevention**: Read the HDM documentation for exact TOML section names.

### BUG 5 — Missing scoring weights
When docked + lid open, BOTH `docked_lid_open` (4 monitors + lid=Opened) AND
`undocked_lid_open` (1 monitor + lid=Opened) match the current state. Without
explicit `[scoring]` weights, HDM's default scoring can pick the wrong profile.
**Fix**: Add `[scoring]` section with `lid_state_match = 10, monitor_match = 5`.
This gives docked_lid_open (4×5 + 10 = 30) > undocked_lid_open (1×5 + 10 = 15).
**Prevention**: When multiple profiles can match the same state, always add scoring.

### BUG 6 — Workspace rule merging in Hyprland 0.55
Even with correct HDM monitor positioning, workspace rules in `monitors.nix`
(mkWorkspaceRules) bind workspaces 1-3 to external monitors. Hyprland 0.55
merges these with the eDP-1 bindings from extraConfig — two `default:true`
for the same workspace breaks Super+1/2/3.
**Fix**: Filter workspaces 1-3 from mkWorkspaceRules: `builtins.filter (w: w > 3)`.
**Prevention**: Never bind the same workspace to two monitors in Hyprland 0.55.

## What Worked (Partially)

- HDM flake input + HM module wiring: correct
- TOML profile structure with conditions: correct syntax
- Static hyprconfig files with exact coordinates: correct
- eDP-1 off-screen park (-30000x0) instead of disable: correct (avoids Hyprland#1274)
- Lid events via UPower D-Bus: correct configuration
- home.activation stub creation with existence guard: correct pattern (BUG 2 fix)

## Lessons for v2

1. **Verify connector names on the T14** before writing HDM profiles:
   ```bash
   hyprctl monitors -j | jq '[.[] | {name, description}]'
   ```

2. **Use description matching with regex** to be connector-agnostic:
   ```toml
   [[profiles.docked.conditions.required_monitors]]
   description = "AOC.*2470W"
   match_description_using_regex = true
   ```

3. **Test HDM dry-run before deploying**:
   ```bash
   hyprdynamicmonitors run --dry-run --config /path/to/config.toml
   ```

4. **Verify the generated config file is correct** before trusting it:
   ```bash
   cat ~/.config/hypr/config.d/99_autogenerated-monitors.conf
   ```

5. **Deploy HDM first in isolation** — get it working with a simple 2-profile config,
   then add dock/lid complexity. Don't try to replace everything at once.

6. **Don't delete the old daemon until HDM is confirmed working** — keep both running
   in parallel during testing. The `omarchy.hyprland.lidSwitch.enable = false` setting
   prevents conflicts.
