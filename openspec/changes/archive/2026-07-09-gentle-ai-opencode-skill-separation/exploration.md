### Review Loop Mechanism

The review/iteration loop spans TWO files with partial separation:

#### sdd-review-policy.md (Local, Manual, NOT Nix-managed)
- 115 lines at `~/.config/opencode/sdd-review-policy.md`
- Defines the HIGH-LEVEL policy:
  - Workflow diagram: explore→propose→spec→design→tasks→apply→review→done|amend
  - Binary decision: reiterate (full cycle) vs redo (re-apply only)
  - Reiterate protocol, guard lines, verify gate, redo escape hatch
  - Artifact expectations, orchestrator expectations
- **Risk**: This file is manually placed and NOT managed by Nix. It survives rebuilds because `opencode.nix`'s orphan cleanup only covers `skills/` and `commands/` directories, not root-level files. However, if the `~/.config/opencode/` directory is ever fully nuked and rebuilt, this file would be lost.

#### sdd-orchestrator.md Review Gate section (Local override of upstream base)
- ~57 lines at lines 410-461 of the deployed version
- Defines the MECHANICAL gate:
  - How to resolve artifact store and locate the review
  - Exact verdict decision table (done→continue, redo→continue, amend→stop, missing→stop)
  - Binary decision presentation via `question` tool
  - Verify gate hard block

#### Relationship
These two files form a **policy/mechanism pair**:
- `sdd-review-policy.md` = the *what* and *why* (high-level rules, diagram, protocols)
- `sdd-orchestrator.md` Review Gate = the *how* (technical implementation of the gate)
- Both are LOCAL (not from upstream), but one is Nix-managed and the other is manual

#### Upstream Contribution
- The vanilla `sdd-orchestrator.md` (431 lines) provides the orchestrator framework, delegation rules, SDD workflow, artifact table, and engram topic key format
- The local override ADDS the review gate mechanism and REMOVES the upstream "Review Execution Contract" (findings ledger, scoped re-review)
- The upstream did NOT have an iteration/review gate — that's a pure NixOS addition

### Risks

1. **sdd-review-policy.md is unmanaged**
   - It lives at `~/.config/opencode/` but is NOT tracked by any Nix file or derivation
   - Survives normal rebuilds (only `skills/` and `commands/` get orphan cleanup) but would be lost on a full nuke-and-rebuild of `~/.config/opencode/`
   - Contradicts the declarative NixOS philosophy — a critical policy file is manually maintained
   - The orchestrator Review Gate (in `sdd-orchestrator.md`) references the policy's verdicts (done/amend/reiterate/redo) but doesn't enforce the policy's existence

2. **Upstream dependency risk**
   - All 30 upstream skills are verbatim copies from `Gentleman-Programming/gentle-ai`
   - If upstream truncates, breaks, or changes a skill, it auto-propagates on next `nix flake update`
   - The `skills.backup/` directory is a manual safety net, not automated

3. **sdd-orchestrator.md divergence risk**
   - The local override (473 lines) removes 26 lines of upstream Review Execution Contract and adds 57 lines of Review Gate
   - If upstream changes the orchestrator structure significantly, the local override may need manual merge
   - Current diff: 127 lines differ between vanilla (431) and local (473)

4. **Agent overlay fragmentation**
   - Agent definitions come from THREE sources: upstream `sdd-overlay-single.json`, local `local-agent-overlays.json`, and `agents.nix` merge logic
   - The `__replace__` marker system in `agents.nix` adds complexity to the merge
   - 7 non-SDD agents (3 JD + 4 review lenses) lack fallback skill instructions (known from #1714)

5. **Local skills are hardcoded in packages.nix**
   - `extraSkills = ./../shared/opencode/skills` is hardcoded in `lib/packages.nix` line 22
   - Adding a new local skill requires no code change (just drop a directory), but removing one would require inventory review since there's no explicit allowlist

6. **Sed patch fragility**
   - `opencode.nix` lines 185-192 patch `sdd-apply` and `sdd-verify` to strip the `<!-- section:model-capable -->` marker
   - If upstream changes the marker format or removes it, the sed command silently becomes a no-op with no alert

### Ready for Proposal

Yes — the exploration provides enough detail for a proposal about clear separation. Key items for the proposal:

- **Primary concern**: `sdd-review-policy.md` should be moved into the Nix pipeline (either as an extraAsset overlay or as a dedicated home.file entry in opencode.nix)
- **Secondary**: Document the override mechanism clearly (which files override which upstream assets)
- **Optional**: Add an allowlist for local skill overrides instead of blanket `extraSkills = ./../shared/opencode/skills`
- **Debt tracking**: 7 agents missing fallback skill instructions (from #1714)
