# Proposal: T14 HDM Migration v2

## Intent

Replace T14's fragile ~290-line custom monitor stack (polling bash daemon + hyprlang conditionals + 300-char bindls + settings.conf + udev drop-in) with HyprDynamicMonitors v1.4.0. HDM provides event-driven monitor management via native Hyprland IPC + UPower D-Bus, eliminating polling, flicker, and race conditions. All 6 v1 bugs addressed by construction.

## Scope

### In Scope
- Add `hyprdynamicmonitors` flake input and wire HM module
- Create HDM TOML config with 4 profiles + fallback + scoring + lid_events
- Create 5 static Hyprland configs (4 profiles + fallback) with exact monitor directives
- Strip old stack: daemon, bindls, hyprlang ifs, settings.conf, udev drop-in, validator script
- Filter `mkWorkspaceRules` to `w > 3` (v1 BUG 6 fix)

### Out of Scope
- Greeter monitor layout (omarchy.greeter.*)
- Other hosts (rog, thinkcentre, mact2)
- `omarchy-hyprland-monitor-watch` socat listener (orthogonal, kept as-is)
- `omarchy.hyprland.lidSwitch.enable = false` (kept as-is)

## Capabilities

> Contract between proposal and specs phases.

### New Capabilities
- `hdm-profiles`: HDM TOML configuration — 4 profiles (docked_lid_open, docked_lid_closed, undocked_lid_open, undocked_lid_closed) + `[fallback_profile]`, scoring weights, lid_events via UPower, description-based monitor matching
- `hdm-hyprconfigs`: Static per-profile Hyprland config files — exact `monitor=` directives preserving dead-zone y=420 (docked-lid-open), eDP-1 off-screen park at -30000x0 (docked-lid-closed), and fallback generic layout

### Modified Capabilities
- `t14-monitor-layout`: REMOVE requirements from CAP-CONDITIONAL, CAP-DAEMON, CAP-SETTINGS, CAP-DRM, CAP-STANDALONE. MODIFY CAP-LIDSWITCH (keep `omarchy.hyprland.lidSwitch.enable = false`; remove T14 bindl + settings.conf writer — HDM handles lid via UPower D-Bus). MODIFY CAP-HOTPLUG (keep `omarchy-hyprland-monitor-watch`; remove T14 daemon polling)

## Approach

1. Add `hyprdynamicmonitors` flake input (`github:fiffeek/hyprdynamicmonitors`, follows nixpkgs)
2. Wire `homeManagerModules.default` into t14 host HM imports
3. Configure `home.hyprdynamicmonitors` with TOML profiles and per-profile hyprconfigs
4. Strip `monitors.nix` extraConfig, add `source` directive pointing to HDM destination
5. Address all 6 v1 bugs: absolute paths (BUG 1), separate destination (BUG 2), description matching (BUG 3), `[fallback_profile]` syntax (BUG 4), explicit scoring (BUG 5), workspace filter `w > 3` (BUG 6)

## Risks

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| `omarchy-hyprland-monitor-watch` race on `monitoradded>>` | Low | HDM `debounce_time_ms=1500` absorbs; benign extra reload at worst |
| UPower regression breaks lid events | Low | UPower already enabled in `modules/hardware/amd-laptop.nix`; add assertion |
| EDID description changes on monitor replacement | Low | `[fallback_profile]` covers unknown monitor sets; user updates TOML |

## Rollback Plan

Revert the commit and `nixos-build switch`. Old daemon script remains in git history. HDM destination (`~/.config/hypr/config.d/99_autogenerated-monitors.conf`) is outside HM management — clean removal with no stale symlinks.

## Dependencies

- `hyprdynamicmonitors` 1.4.0 (in nixpkgs unstable)
- UPower (already enabled in `modules/hardware/amd-laptop.nix`)
