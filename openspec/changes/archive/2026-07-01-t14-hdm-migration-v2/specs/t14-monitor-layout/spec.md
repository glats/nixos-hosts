(Reason: Replaced by HDM profile selection — static configs per profile eliminate parse-time conditionals)
(Migration: HDM selects correct profile based on monitor + lid state; `source` directive in `monitors.nix` points to HDM destination)

(Reason: Replaced by HDM systemd service — event-driven, no polling)

## MODIFIED Requirements

### Requirement: CAP-LIDSWITCH — Single-owner Lid-Switch Runtime Control

Lid switch events MUST be handled by HDM via UPower D-Bus in the `[lid_events]` section. Omarchy's default lid-switch `bindl` MUST remain disabled (`omarchy.hyprland.lidSwitch.enable = false`). T14's `bindl` directives (300-char shell commands writing to `settings.conf`) are REMOVED.

| Req | Requirement |
|-----|-------------|
| REQ-LID-1 | `omarchy.hyprland.lidSwitch.enable = false` MUST be set in t14 host config |
| REQ-LID-2 | T14's `bindl` directives writing to `settings.conf` are REMOVED |
| REQ-LID-3 | HDM `[lid_events]` section MUST handle lid state changes via UPower D-Bus |
| REQ-LID-4 | On lid close, HDM MUST select `docked_lid_closed` or `undocked_lid_closed` profile |
| REQ-LID-5 | On lid open, HDM MUST select `docked_lid_open` or `undocked_lid_open` profile |

(Previously: T14's `bindl` was sole writer to `settings.conf`, applying layout via `hyprctl keyword` and repositioning externals)

#### Scenario: Lid close without race

- GIVEN `omarchy.hyprland.lidSwitch.enable = false`
- AND HDM `[lid_events]` is enabled
- WHEN lid closes
- THEN UPower D-Bus emits lid "Closed" signal
- AND HDM selects `docked_lid_closed` or `undocked_lid_closed` profile
- AND no `hyprctl reload` from omarchy's `bindl` interferes

#### Scenario: Lid open restores layout

- GIVEN lid was closed
- WHEN lid opens
- THEN UPower D-Bus emits lid "Opened" signal
- AND HDM selects `docked_lid_open` or `undocked_lid_open` profile
- AND correct profile applies (eDP-1 enabled if undocked, externals at y=420 if docked)

### Requirement: CAP-HOTPLUG — Monitor Hotplug Recovery

Monitor addition/removal at runtime MUST be detected by HDM via native Hyprland IPC. `omarchy-hyprland-monitor-watch` socat listener is KEPT (orthogonal, calls `hyprctl reload` on `monitoradded>>`). T14 daemon polling is REMOVED.

| Req | Requirement |
|-----|-------------|
| REQ-HOTPLUG-1 | On `monitoradded>>` or `monitoraddedv2>>` socket2 event, `omarchy-hyprland-monitor-watch` MUST execute `hyprctl reload` |
| REQ-HOTPLUG-2 | T14 daemon polling loop is REMOVED |
| REQ-HOTPLUG-3 | HDM MUST detect monitor changes via native Hyprland IPC and apply correct profile |
| REQ-HOTPLUG-4 | HDM `debounce_time_ms = 1500` MUST absorb rapid dock/undock transients |
| REQ-HOTPLUG-5 | The two layers (omarchy reload + HDM profile apply) are independent and idempotent |

(Previously: T14 daemon polled `hyprctl monitors -j` every 2 seconds and re-applied layout based on lid state)

#### Scenario: Dock connected mid-session

- GIVEN laptop is undocked, HDM is running
- WHEN dock with 3 externals is connected
- THEN `omarchy-hyprland-monitor-watch` fires `hyprctl reload` via monitoradded handler
- AND HDM detects monitor change via native IPC
- AND HDM applies `docked_lid_open` or `docked_lid_closed` profile (based on current lid state)

#### Scenario: Undock mid-session

- GIVEN laptop is docked, HDM is running
- WHEN dock is disconnected
- THEN HDM detects monitor removal via native IPC
- AND HDM applies `undocked_lid_open` or `undocked_lid_closed` profile (eDP-1 enabled if lid open)
