## Correct the unenforced six-request proposal

The six-request ceiling at `login-isolation-check.md:96–108` is an earlier proposal, not a user-imposed numeric limit and not an enforced receipt. Six logical workflow stages are not six HTTP requests. Delegation, worker tools/tests, result resumption, durable Engram write/readback, and risk/refuter/validator reviews normally require multiple model turns. Refusing a continuation because of an artificially small cap is a **budget stop**, not evidence of native runtime incompatibility.

Recommend the following explicit private-cycle budget for parent disclosure before launch:

- **20 total session request preparations**, shared by every role/session in one standalone process, including auxiliary title/generate requests and any repreparation after failures. This conservatively bounds generation opportunities; it is not an exact count of completed model turns.
- Independently **20 model HTTP middleware admissions**, including attempts that fail or are never actually sent after admission. Reject admission 21 before the transport handler. This is the enforceable unit at the native public hook boundary, **not** a count of TCP exchanges, redirects, OAuth requests, catalog traffic or MCP calls.
- Explicit **HTTP-only private OpenAI transport**, retaining OAuth, provider ID, Sol/Luna model routes, role definitions and grants. Reject any unexpected WebSocket handshake instead of silently falling back. This is a deliberate private test transport override, not a production change or an account/model replacement.
- **No automatic provider retry**; latch the whole process budget on the native retry hook, HTTP status error, or tool hook error. Reject later admissions after the latch. Parent stops on the first real failure and launches no later stage or replacement model. Budget exhaustion/deadline/token truncation must remain separately classified from compatibility failures.
- `options.maxTokens = 8192` for context/title/session-generate requests and at most **8 agent steps** per admission; preserve a smaller existing step limit. No automatic compaction in this small fixture: reject it before dispatch rather than allowing an uncapped provider checkpoint request or inventing a compaction result.
- **15-minute admission deadline** plus a separately verified parent process-group wall-clock watchdog that interrupts/kills the private standalone process and its descendants. The hook deadline alone does not stop an already admitted stream or hung tool. No restart/reload workaround or second process to reset the budget.

The six stages can allocate roughly one parent dispatch, four to six worker tool turns, two to four parent resume/persistence turns, two turns per review role, plus one title. That is a planning estimate, not a fabricated receipt or a guarantee of completion within 20. Use only a tiny isolated fixture and sequential review stages. Do not front-load broad repository exploration or paid fallback. A cycle that exhausts the agreed cap is incomplete; do not automatically enlarge it.
