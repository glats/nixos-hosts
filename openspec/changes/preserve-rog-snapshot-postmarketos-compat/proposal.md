# Proposal: Preserve Rog Snapshot with postmarketOS Compatibility

## Intent

Keep `sync-opencode-remote` a complete Rog-generated OpenCode snapshot transfer while making only proven OnePlus runtime exceptions after transfer. The OnePlus has local OpenAI OAuth and validates the required `openai/*` IDs, so it must retain Rog's `openai-medium` model graph rather than receive an OpenCode Go fallback. It must not gain an independently maintained profile.

## Scope

### In Scope
- Preserve the existing rsync allowlist and Rog source snapshot unchanged; apply target actions only after a successful non-dry-run transfer.
- Preserve all copied `openai/*` agent model IDs exactly as generated by Rog's `openai-medium` profile; explicitly supersede the prior OpenCode Go fallback.
- Require OnePlus to use its own local OpenAI OAuth credential; never inspect, copy, rewrite, or transfer authentication secrets.
- Disable BrowserMCP only for the OnePlus target, because its startup invokes `kill(0, SIGKILL)` on postmarketOS; retain it in Rog and all non-OnePlus flows.
- Preserve the existing target-only exclusions for `rtk.ts` and the Gentle-AI-dependent skill-registry integration, with focused Go tests and dry-run reporting.

### Out of Scope
- A OnePlus-specific Nix, Home Manager, routing, or OpenCode profile.
- Changes to Rog's generated configuration, `openai-medium` routing, credentials, or rsync snapshot boundary.
- Installing RTK, supporting Gentle AI on postmarketOS, or copying OpenAI authentication material.

## Capabilities

### New Capabilities
- `postmarketos-opencode-snapshot-compat`: Transfer a full Rog snapshot, preserve its locally authenticated OpenAI model graph, and apply auditable OnePlus-only runtime exclusions.

### Modified Capabilities
None.

## Approach

Keep the existing backup, rsync, dependency-install, and remote-command flow. Remove the model-rewrite rule: OpenAI model assignments pass through unchanged and resolve with local OAuth. Apply an idempotent, exact OnePlus-only exclusion set for RTK, skill registry, and BrowserMCP. The stage preserves unrelated assets, does not handle credentials, and reports dry-run actions without mutation.

## Affected Areas

| Area | Impact | Description |
|------|--------|-------------|
| `pkgs/nixos-scripts/cmd/sync-opencode-remote/main.go` | Modified | Remove model fallback; apply exact target-only BrowserMCP and existing exclusions. |
| `pkgs/nixos-scripts/cmd/sync-opencode-remote/main_test.go` | Modified | Preserve-model, local-auth boundary, exact exclusions, idempotency, and dry-run tests. |

Host scope: Rog remains the unmodified snapshot source; the OnePlus postmarketOS remote is the sole transformed target.

## Risks

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| Local OAuth is absent or expires | Medium | Require local `opencode auth list` confirmation; do not substitute or transfer credentials. |
| BrowserMCP exclusion leaks beyond OnePlus | Low | Target the exact OnePlus post-sync path and test source/non-OnePlus preservation. |

## Rollback Plan

Revert the target-only BrowserMCP and existing-exclusion changes and deploy the prior binary. Restore the pre-transfer remote backup if needed. Re-enable BrowserMCP on OnePlus only after its postmarketOS process-group kill behavior is fixed; Rog source files and local OAuth credentials remain untouched.

## Dependencies

- Confirmed OnePlus local OpenAI OAuth and validation of all required `openai/*` model IDs.

## Success Criteria

- [ ] Sync copies the complete existing Rog allowlisted snapshot before any target adaptation.
- [ ] Every copied `openai/*` agent model, including `openai/gpt-5.6-terra`, remains unchanged and resolves through local OAuth.
- [ ] Only OnePlus loses BrowserMCP; Rog and non-OnePlus flows retain it, while target-only RTK and skill-registry exclusions remain intact.
- [ ] Dry run reports planned compatibility actions without remote mutation.
- [ ] Go tests cover unchanged OpenAI models, no fallback, local-auth boundaries, exact exclusions, idempotency, and dry-run behavior.
