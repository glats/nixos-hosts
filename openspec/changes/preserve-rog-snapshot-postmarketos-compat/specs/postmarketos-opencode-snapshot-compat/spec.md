# postmarketOS OpenCode Snapshot Compatibility Specification

## Purpose

Make a Rog-generated OpenCode snapshot usable on the OnePlus postmarketOS target without creating or maintaining a target-specific profile.

## Requirements

### Requirement: Snapshot-First Transfer

The system MUST retain the existing Rog snapshot boundary and MUST apply OnePlus compatibility only after a successful, non-dry-run transfer. It MUST NOT transform, remove, or rewrite source snapshot assets before or after transfer.

#### Scenario: Successful transfer precedes compatibility adaptation

- GIVEN [Hosts: rog, OnePlus] a valid Rog-generated snapshot and reachable target
- WHEN a non-dry sync completes its transfer
- THEN the target receives the complete allowlisted snapshot before compatibility actions occur

#### Scenario: Failed transfer prevents compatibility adaptation

- GIVEN [Hosts: rog, OnePlus] a transfer that fails
- WHEN the sync command terminates
- THEN it MUST NOT run target compatibility actions

#### Scenario: Rog source snapshot is retained

- GIVEN [Host: rog] a source snapshot with OpenAI models and BrowserMCP
- WHEN a sync or dry run completes
- THEN the source snapshot remains byte-for-byte unchanged

### Requirement: OpenAI Model Graph Preservation

The system MUST preserve every copied `openai/*` agent model reference exactly as generated by Rog's `openai-medium` profile. It MUST NOT replace OpenAI models with an `opencode-go` fallback or alter agents without an explicit model.

#### Scenario: OpenAI model references remain unchanged

- GIVEN [Host: OnePlus] copied configuration with multiple `openai/*` agent models, including `openai/gpt-5.6-terra`
- WHEN compatibility is applied
- THEN every `openai/*` model reference remains byte-for-byte unchanged

### Requirement: Local OAuth Authentication Boundary

The system MUST require the OnePlus to retain and use its locally authenticated OAuth state for copied OpenAI models. It MUST NOT read, inspect, copy, transfer, rewrite, delete, or otherwise handle authentication files, secrets, tokens, or credentials.

#### Scenario: Compatibility does not access credentials

- GIVEN [Host: OnePlus] local OAuth state and source-side authentication artifacts
- WHEN a sync, compatibility stage, or dry run executes
- THEN no authentication artifact is read, transferred, or mutated

### Requirement: Bounded OnePlus Integration Exclusion

The system MUST make only `rtk.ts`, the Gentle-AI-dependent skill-registry integration, and BrowserMCP unavailable on the OnePlus postmarketOS target. BrowserMCP MUST be disabled only because its trace-proven startup kills the OnePlus XRDP session; it MUST remain available in Rog and every non-OnePlus flow. The system MUST NOT alter unrelated snapshot assets.

#### Scenario: Exact OnePlus exclusions are applied

- GIVEN [Host: OnePlus] a copied snapshot containing all three named integrations
- WHEN compatibility is applied
- THEN none of the three integrations remains loadable by the OnePlus runtime

#### Scenario: BrowserMCP is preserved outside the OnePlus target

- GIVEN [Hosts: rog, non-OnePlus] a source snapshot or non-OnePlus flow containing BrowserMCP
- WHEN a OnePlus compatibility stage is applied for a separate target
- THEN BrowserMCP remains present and available outside that OnePlus target

#### Scenario: Unrelated assets are preserved

- GIVEN [Host: OnePlus] a copied snapshot containing an unrelated plugin or skill asset
- WHEN compatibility is applied
- THEN that asset remains unchanged

### Requirement: Idempotent Compatibility State

The system MUST produce the same compatible target state when its compatibility stage is applied repeatedly to an already compatible snapshot, including the BrowserMCP exclusion.

#### Scenario: Repeated application has no additional effect

- GIVEN [Host: OnePlus] a snapshot already adapted successfully
- WHEN compatibility is applied again
- THEN the resulting configuration and managed asset set, including BrowserMCP's excluded state, are unchanged

### Requirement: Non-Mutating Dry Run

The system MUST report every compatibility action, including pending RTK, skill-registry, and BrowserMCP exclusions, that a non-dry sync would perform during dry run. It MUST NOT mutate the target, source, or local OAuth state.

#### Scenario: Dry run reports without changing the target

- GIVEN [Hosts: rog, OnePlus] a dry sync whose snapshot would need integration exclusions
- WHEN dry run executes
- THEN it reports each planned exclusion and performs no mutation

### Requirement: Failure and Configuration Preservation

The system MUST return failure when compatibility cannot produce valid configuration, MUST NOT report the sync as successful, and MUST preserve the pre-transfer backup for recovery. It MUST NOT apply any exclusion after invalid JSON.

#### Scenario: Invalid copied configuration fails before BrowserMCP exclusion

- GIVEN [Host: OnePlus] copied malformed JSON configuration containing a BrowserMCP entry
- WHEN compatibility is attempted
- THEN the command fails, retains the recovery backup, and applies no integration exclusion
